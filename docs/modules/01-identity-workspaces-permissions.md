# M01 企业、工作空间、身份与权限

关联：REQ-001–004、050。模块拥有企业与项目成员关系，其他模块通过授权服务核查，不自行解释角色字符串。

## 1. 领域对象

Tenant 代表客户企业；Project 代表品牌或业务工作空间；BrandProfile 为项目内可版本化资料。User 可以属于多个 Tenant，同一用户切换企业时重新获取范围化会话上下文。

Membership 保存企业角色、状态和 auth_version；ProjectMembership 保存项目范围与项目角色。Invite 包含目标企业、角色、项目范围、过期时间及一次性状态；不能通过客户端修改邀请获得更高权限。

## 2. 权限矩阵

| 动作 | Owner | Admin | Member | Approver | Viewer |
| --- | --- | --- | --- | --- | --- |
| 读取获授项目 | 是 | 是 | 是 | 是 | 是 |
| 创建与执行任务、改草稿 | 是 | 是 | 是 | 可配置 | 否 |
| 评论、要求修改、接受交付物 | 是 | 是 | 在获授项目 | 在获授范围 | 否 |
| 批准外部发布/预算等业务操作 | 是 | 是 | 否 | 在获授范围 | 否 |
| 连接账户与配对设备 | 是 | 是 | 经项目授权 | 否 | 否 |
| 使用模板/配置自己的 Agent、技能与计划 | 是 | 是 | 在获授范围且有管理权 | 可配置 | 否 |
| 发布共享项目规则、技能、方案与团队配置 | 是 | 是 | 可提交候选，发布需授权 | 否 | 否 |
| 邀请普通成员 | 是 | 是 | 否 | 否 | 否 |
| 指定 Owner/Admin、改计费和企业删除 | 是 | 否 | 否 | 否 | 否 |

Owner/Admin 可管理全企业项目；其他角色须有项目成员关系。操作授权还需匹配工具、连接账户、预算、设备目录和具体操作，角色允许不代表资源全部开放。被显式停用优先于允许；最后一个 Owner 不可直接退出，先转移所有权。

API 的 agent.manage、skill.manage、workflow.manage、asset.share 分别映射到上述动作与项目范围；security_revoke 只对获授项目管理者开放。Agent Group 成员是执行配置，不是新增人类成员或独立授权主体，所有调用取本次用户/服务身份与项目策略交集。共享产物不授予整段私有会话或连接凭证。

## 3. 认证设计默认

首期采用产品自身身份体系，邮件一次性验证码/邀请与会话机制；企业 OIDC/SSO 为扩展。凭证发送在真实开发时接入正式服务，本套文档不触发任何邮件或外部消息。

Web 使用 Secure、HttpOnly、SameSite=Lax 的会话 cookie，写操作要求 CSRF token 并检查 Origin。会话可撤销，敏感管理动作要求近期认证；平台 Admin 的独立身份与 MFA 在 M1 开放后台之前验收，企业管理员 MFA 按企业策略启用。

Desktop/扩展通过系统浏览器和 PKCE 完成产品登录，短时 code 换取范围化 token，refresh token 存系统凭证库或扩展受控存储。不得将供应商 Key、产品 refresh token 放进回调 URL 或页面脚本。

## 4. 请求授权顺序

验证登录 → 查询有效企业成员 → 检查项目范围 → 检查动作权限 → 检查资源归属和状态 → 形成执行 scope → 执行前再检查会变化的授权版本。

未知资源与跨企业资源对普通用户统一返回未找到，避免泄露存在性。服务间身份绑定企业和用途，不接受模型传来的任意 tenant_id。数据库连接池内使用事务级企业上下文，事务结束自动清理。

## 5. 撤销与一致性

成员移除递增 auth_version，撤销会话并阻止新任务/下载/设备操作。已排队的用户任务在领取时复核；依赖其个人授权的运行中步骤停在安全边界，管理员可明确重新归属。企业共享产物由企业继续持有。

连接撤销立即禁新请求，清理可撤销凭证；已被平台接受的操作记录结果。设备撤销停止新命令、取消未领取命令并删除本地配对凭证；离线设备恢复后先同步撤销状态。

## 6. 接口与验收

接口族包括企业/项目读取与创建、成员邀请、成员移除、会话退出、连接撤销和设备撤销，详见 OpenAPI。每个写入有审计事件，邀请接受与移除支持幂等。

验收同时覆盖 API、SSE、对象下载、报表导出、后台执行及设备命令；仅验证页面菜单隐藏不足以证明权限有效。

## 7. 平台管理员身份与数据范围

REQ-083–085/094–096/100 另建 AdminPrincipal、AdminSession、AdminRoleVersion 和 AdminRoleBinding；企业 Owner/Admin 不自动成为平台管理员。八类预设角色和逐动作字段权限见 [后台规格](../product/08-admin-dashboard.md) 与 [目录契约](../contracts/admin-permission-catalog.json)。后台采用独立 cp_admin_session、MFA、CSRF 和权限版本，普通用户/设备凭证不可替换。

后台请求顺序为独立会话及 MFA → 有效角色绑定 → 注册动作和显式拒绝 → 全局/企业/项目范围 → 字段、状态、金额及风险策略 → 事务与审计。全局冻结用户必须有全局权限；企业范围管理员只能暂停该企业成员关系，不能借全局用户 ID 影响其他企业。权限授予须在操作者可委派权限上限内，超管不具备关闭硬约束或删除审计的旁路。

内容管理员在被授予的范围内可直接管理正文；客服依限时支持会话获得限定只读视图，始终显示真实管理员身份。撤销后台绑定同样递增权限版本，旧会话、异步任务、导出下载和恢复入口再次检查。实现与身份升级迁移见 [后台技术设计](../technical/11-admin-control-plane.md)。
