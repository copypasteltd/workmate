> 历史来源说明：本文件保留第一轮需求梳理。现行完整规格、接口、阶段和验收以 [文档总目录](README.md) 中的分册为准。

版本：v0.1（讨论稿）  
日期：2026-10-18，Asia/Taipei  
适用范围：产品定义、业务需求与能力边界；尚未冻结技术选型、预算和交付排期。

## 1. 产品定义与信息状态

建议将产品定义为：**面向在港企业、以 marketing 团队为首批用户，通过 Web、Chrome 扩展和桌面客户端交付营销生产、效果分析及重复工作自动化的企业 Agent 服务。**

用户提交目标与必要资料，Agent 在获授权的范围内执行任务，交付可以检查、修改、下载和复用的结果。公司内部 AI 网关统一承担模型访问、能力路由和用量管理。

本稿中的「已确认」来自用户明确陈述；「建议」是本轮提出的产品方案；「待验证」需要实际接口或试点证据。建议与示例均不代表用户已批准的开发范围。

| 编号 | 已确认内容 | 对产品的约束 |
| --- | --- | --- |

### 1.2 本稿采用的解释

- Codex 为已确定内核，与底层模型和企业平台分别配置，集成边界见 [现行技术设计](technical/02-runtime-and-ai-gateway.md)。
- 「类似 Grok Bot」采用任务委派、后台执行、持续上下文与结果交付的方向；具体界面和全部功能不作一比一复刻承诺。
- 「Google website analyze」暂按 GA4 网站行为分析理解，同时把 Search Console 和网站页面诊断单独列出，避免遗漏。
- 「在港企业」描述目标客户所在地；服务器部署区域、模型处理区域、跨境数据路径尚未确认。
- Web、扩展、桌面端是能力入口；具体开发顺序及收费方案仍可调整。

## 2. 产品定位与首批用户

官网目前围绕 AI、网络和支付基础设施提供企业服务，并包含企业知识平台与 AI 应用集成。这说明新产品可以与现有企业服务形成衔接；并不能据此认定公司已经具备本稿中的营销生成或广告分析能力。[公司官网](https://copypaste.hk/)

建议首期价值主张：**让现有客户的 marketing 团队，用同一套品牌资料完成素材生产和效果复盘，并把验证有效的步骤沉淀为可重复执行的任务。**

| 用户角色 | 典型工作 | 希望获得的结果 |
| --- | --- | --- |
| 内容与设计人员 | 从 brief 制作多版本素材、改文案、调尺寸、做短视频 | 可修改、可交付、符合品牌要求的素材包 |
| 投放与增长人员 | 汇总平台数据、解释波动、提出下一轮测试 | 数字可信、来源清楚、可执行的分析报告 |
| marketing 负责人 | 审核内容、控制预算、统筹多人协作 | 清楚看到任务状态、版本与成本 |
| 企业管理员 | 管理成员、品牌资料、平台授权和设备 | 企业之间隔离，权限和用量可管理 |

广告代理商、多客户代运营及其他部门可作为扩展用户；不把其全部需求加入首期。

## 3. 三种使用入口

### 3.1 能力分工

| 维度 | 云端 Web | Chrome 扩展 | Desktop 客户端 |
| --- | --- | --- | --- |
| 主要用途 | 发起任务、上传资料、查看进度与产物 | 在当前网页使用 Agent、采集授权上下文、连接本地文件能力 | 长时间批处理、目录任务、本地程序与完整工作台 |
| 本地文件 | 手动上传、下载；支持时通过浏览器文件选择器授权读写 | 授权文件选择；更深的文件操作可借助本地桥接组件 | 对授权目录读写、索引、批量处理和监听 |
| 浏览器上下文 | 用户提供链接或资料；云端浏览器使用独立会话 | 用户选中的页面、文本、截图或获准的站点操作 | 可组合扩展或独立浏览器执行器 |
| 本地程序调用 | 不提供直接本机执行 | 需独立安装的本地组件 | 由原生执行器提供 |
| 后台执行 | 云端任务可在网页关闭后继续 | 云端任务可继续；本地步骤受浏览器和本地组件状态影响 | 设备在线、程序运行且授权有效时执行本地步骤 |
| 成本特征 | 云端算力、模型、素材存储和流量 | 增加扩展发布与本地桥接维护 | 增加多系统安装、升级、签名及本地执行维护 |

浏览器官方文档支持用户通过文件选择器授权访问文件或目录；扩展也可通过 Native Messaging 与原生应用通信。因此，**基础本地文件操作不必等到扩展版；持续目录调度与程序调用需要另行设计本地执行能力**。参见调研记录中的 S07、S08。

### 3.2 统一体验要求

建议三端共用企业身份、品牌项目、任务编号、产物版本和用量记录。用户可以在 Web 发起任务，在桌面处理本地步骤，再回到 Web 审阅结果。

切换入口不代表权限自动扩大。任务使用新设备、新目录或新平台账户时，应取得相应授权。设备离线时，依赖该设备的步骤进入等待状态；不依赖设备的云端步骤可以继续。

一旦需要本地桥接组件，扩展方案也存在本地安装成本。建议复用同一个本地执行器，供扩展与完整桌面客户端使用，减少重复建设。

### 3.3 持续 Agent、会话与任务

建议首期提供一个可配置的 marketing Agent，保存职责、品牌范围、工作偏好及获准使用的工具。每次委派形成独立任务，会话保留沟通上下文，产物归属到具体项目；这些对象不应只存在于某一台客户端。

用户再次发起工作时可以复用资料，并查看 Agent 过去完成的任务。多个专业 Agent、Agent 间协作和每个 Agent 独占的云电脑分别作为后续范围确认。持续服务的可用性与空闲时是否持续运行模型需要分开设计和计费。

## 4. 业务域 A：营销素材生产

### 4.1 从 brief 到素材包

输入包括活动目标、受众、渠道、语言、品牌资料、参考素材、商品信息、尺寸、截止时间与费用上限。

建议流程：补齐影响交付的关键信息 → 形成创意方向与制作清单 → 生成或编辑素材 → 叠加文字与品牌元素 → 预览和修改 → 导出版本化素材包。

交付物应包含实际文件、使用说明及可恢复的编辑信息，能够追踪到任务、品牌版本和所用素材；具体编辑工程格式另行确认。

### 4.2 能力拆分

| 能力 | 具体需求 | 完成标准与边界 |
| --- | --- | --- |
| 品牌资料库 | Logo、品牌色、字体、语言风格、产品资料、禁用表达和参考风格 | 按企业及品牌分隔；有版本；每次任务明确采用哪一版 |
| 图片生成 | 商品广告图、场景图、活动视觉和社交媒体素材 | 能交付真实图像文件；支持按反馈修改与批量变体 |
| 图片编辑 | 背景替换、局部修改、扩图、素材组合等 | 按实际接入模型逐项开放，不把所有编辑功能视为同一种能力 |
| 文字与字体 | 繁中、英文及混排，字号、字重、间距、换行与品牌字体 | 使用实际字体排版；文案可单独修改；素材记录字体来源与使用范围 |
| 多尺寸适配 | 按渠道输出横版、方版、竖版等固定规格 | 检查裁切、文字溢出和安全区域；不只做等比例缩放 |
| 视频策划 | 短视频脚本、分镜、字幕文案和制作清单 | 策划交付与实际成片分开标识 |
| 基础视频成片 | 用上传或生成素材完成固定模板、字幕、Logo、音乐和导出 | 建议首期验证一种短视频规格，例如 15 秒竖版；最终规格由试点确认 |
| 生成式视频 | 文生视频、图生视频、参考素材驱动的视频等 | 依赖内部网关对应能力；有异步状态、失败处理与成本记录 |
| 特效与动效 | 字幕动画、转场、镜头运动、合成；进一步支持抠像、修复等 | 先确定效果目录与示例，再逐项验收；基础动效与 AI 视频处理分开计量 |
| 版本及导出 | 并排预览、局部修改、恢复历史版本、下载素材包 | 修改文案不应强制重新生成全部图像；导出可定位对应版本 |

文字排版建议作为独立编辑步骤：图片模型负责视觉素材，排版工具负责准确文字及布局。用户所说的「字体」暂解释为选字体、排版和文字效果；设计完整字体家族需作为独立需求确认。

图片、视频、配音、识别等 AI 能力全部通过内部网关调用。已有文本推理模型并不证明这些媒体能力已在内部网关开放。

### 4.3 示例工作流 W01

用户：“用我们的品牌资料，为本周活动做三套社交广告图，输出繁中和英文版本，再做一条短视频。”

Agent 应确认促销信息与素材范围，建立交付清单，分别执行图片、排版、视频步骤，呈现可修改的预览，再导出素材。缺少视频生成接口时，应清楚区分模板成片能力与生成式视频能力，并说明本次可交付范围。

## 5. 业务域 B：广告、网站与搜索分析

### 5.1 数据与输出

| 数据域 | 建议接入对象 | 主要分析输出 |
| --- | --- | --- |
| Google Ads | 获授权广告账户的投放数据 | 消耗、曝光、点击、转化、转化价值、广告系列与素材表现 |
| Meta Ads | 获授权广告账户的数据 | Facebook / Instagram 广告表现及平台可提供的维度 |
| 网站行为 | GA4 | 流量来源、着陆页、参与、事件与关键转化路径 |
| 搜索表现 | Google Search Console | 查询、页面、展示、点击与搜索表现趋势 |
| 页面诊断 | 用户授权的网站范围、页面内容与技术信息 | 内容结构、索引相关线索、内链及改进清单 |
| GEO / AI 搜索可见性 | 经定义的问句集、模型或产品、地区、语言与观测时间 | 样本中的品牌提及、引用及变化；作为专项观测 |
| 人工导入 | 平台导出 CSV / XLSX | 在自动连接器完善前验证分析价值，并保留导入路径 |

Meta 的广告分析、自然内容表现、发帖、私信及客户线索处理分别定义。首期「Meta 系」建议聚焦广告数据分析，避免一次承担全部平台功能。

### 5.2 分析可信度要求

1. 每个数字可追溯到原始文件或查询结果，记录账户、时间区间、时区、币种、过滤条件、数据更新时间和口径。
2. 聚合与指标计算由确定性的计算工具完成，模型负责解释与建议。CTR、CPC、CPA、ROAS 等明确分子、分母及零分母处理。
3. 汇总比率使用汇总后的分子、分母重新计算；不直接平均各广告的 CTR 或 ROAS。
4. 平台归因转化与 GA4 转化分开呈现，注明归因窗口和定义。跨平台转化可能重叠；不直接相加为去重业绩。
5. 多币种默认分别统计；如需换算，记录汇率、日期与来源。没有完整成本时，不把 ROAS 写成企业利润或 ROI。
6. 区分观察、推测和建议。数据不足、追踪缺失、低样本和迟到转化应影响结论表达。
7. 报告包含结果、证据、可能解释和下一步实验。未经验证的相关关系不作为确定因果。

### 5.3 SEO 与 GEO 的边界

SEO 建议提供有页面证据的诊断及修改建议，并用后续搜索和网站数据评估变化。CMS 写回和自动发布属于单独的执行能力。

GEO 建议先定义可重复的观测方法，记录问句、语言、地区、时间、模型版本及是否开启检索。模型 API 样本与消费者实际使用的 AI 搜索产品可能不同，应分别标识，不能据 API 回答推断所有用户的搜索可见性。

Google 的官方说明将其 AI 搜索功能的流量纳入 Search Console 的整体 Web 搜索数据；这不足以提供跨所有 AI 产品的完整 GEO 归因。因此不承诺统一的「全网 GEO 排名」或必然被引用。参见调研记录 S11。

### 5.4 示例工作流 W02

用户：“复盘过去两周 Google 和 Meta 广告，找出表现下降的活动，并提出下一轮素材测试建议。”

Agent 应读取获准的数据源或上传文件，检查日期与口径，计算指标和变化，给出证据链接，再将待验证的素材假设转为下一轮 brief。素材文件与投放 creative ID 建立对应关系，帮助后续复盘；命名或匹配不足时允许用户补充映射。

## 6. 业务域 C：企业重复流程优化

优先沉淀前两个业务域中已经反复发生的工作，例如收集素材、按规则命名和归档、生成周报、整理会议行动项、读取 SOP 后填写固定交付模板。

每个可重复工作流至少定义：触发方式、输入、步骤、可用工具、数据范围、输出、完成标准、成本上限、失败处理和需要人工处理的节点。

建议先支持可编辑的任务模板和手动触发，再增加定时执行与事件触发。跨系统写入应能识别重复请求，避免重试造成重复发帖或重复修改。

首期分析建议与实际发布分开交付。后续发布内容、修改广告预算或执行其他产生外部影响的操作时，应根据企业授权策略执行，并提供对象、变更内容和操作结果；不要求普通读取或每一步素材处理都逐次确认。

示例 W03：每周按模板汇总广告数据和已完成素材，生成负责人可审阅的周报；定时触发上线前先验证同一模板的手动运行。

## 7. 三端共用的平台能力

| 模块 | 必要需求 |
| --- | --- |
| 企业与成员 | 企业隔离、成员邀请、项目访问范围；建议初始区分管理员、执行成员、审核成员和只读成员 |
| 持续 Agent 配置 | 名称、职责、品牌资料、工具范围、工作偏好和任务历史；配置变更有版本 |
| 品牌与项目 | 一个企业可管理多个品牌或活动；资产、连接器和任务属于明确的项目范围 |
| 任务中心 | 创建、排队、执行、中断、取消、重试、继续；显示正在处理的步骤和已完成产物 |
| 长任务 | 云端已接受的任务不依赖前端页面一直打开；支持断线后查询状态与恢复进度 |
| 资料与记忆 | 企业、品牌、项目和个人信息有明确作用范围；可查看、更新和删除持久资料 |
| 连接器 | OAuth 或其他正式授权、账户选择、权限撤销、失效提示、刷新、同步状态和数据截止时间 |
| 产物管理 | 输入与输出关联、版本、预览、下载、保留周期、失败时可保留的部分产物 |
| 用量与成本 | 按企业、成员、任务和能力记录用量；任务预算、并发和额度可管理 |
| 运营后台 | 客户接入、授权故障、任务故障与用量排查；运营人员访问有范围和记录 |

建议统一任务状态：待补充资料、排队、执行中、待授权、等待设备、成功、部分完成、失败、已取消。前端显示的进度应来自真实步骤，不编造百分比或完成时间。

## 8. 执行、数据与服务要求

### 8.1 AI 请求与业务请求

所有语言模型、图片、视频、语音、向量化、重排及其他 AI 服务请求，均经过公司内部 AI 服务边界。工具脚本、插件及后台任务也遵守该路径；不只约束聊天入口。

Google、Meta、文件存储等业务 API 保持各自协议，通过应用连接器访问。「OpenAI 规范」不意味着这些业务 API 也要改成 OpenAI 请求格式。

桌面端及扩展使用本产品的设备或用户凭证；供应商主密钥留在服务器端。模型只能调用应用实际授权的能力，不能仅凭网页或文件中的指令扩大权限。

### 8.2 本地文件与数据边界

读取、写入、同步云端、用于 AI 推理分别说明范围。即使原始文件留在本地，发往云端模型的文本、图片、截图及工具结果仍可能包含文件内容，产品应向用户准确说明。

可配置资料保留、删除、导出与日志范围。企业资产、授权凭证及品牌资料不得跨企业混用。部署区域与下游模型处理区域需确认，不能仅凭内部服务器位置宣称数据始终留港。

### 8.3 可靠性与资源管理

- 长任务支持超时、重试、取消和检查点；重试不应重复产生已完成的外部写入。
- 媒体处理分配独立并发与费用限制，避免单个视频任务耗尽整个客户的任务资源。
- 浏览器执行器限制标签页及会话数量，在任务结束、失败和取消时释放不再需要的资源；保留用户原有页面。
- 建议客户端采用原生安装和执行，不依赖用户额外安装 Docker 或 WSL；操作系统支持范围待试点确认。
- 生产云端的任务隔离、计算环境与部署方式需要另做设计；本稿不指定实施技术。

本次工作受用户明确约束：所有文档存放于 `docs/`，不得调度本地 Docker、WSL 等虚拟化环境；若使用浏览器，需关闭不再使用的标签页。本轮仅使用检索及 HTTP 读取资料，没有启动这些环境或可见浏览器。

### 8.4 香港客户体验

建议首期支持繁中与英文内容、港币费用展示、客户账户时区与报表时区标识。是否需要粤语口播、简体中文、特殊字体及特定行业术语，由试点素材确认。

界面、任务提示及报表优先使用用户熟悉的业务语言；模型名、token、API 等技术信息仅在设置和用量管理等必要位置展示。

## 9. 商业模式与成功标准

建议验证「企业订阅或席位 + 能力用量」的组合，并把首次接入、品牌资料整理、连接器配置及定制流程作为可单独计价的服务。具体价格与计费方式尚未确定。

计费不宜只按客户端分档：Web 用户也可能产生高额视频成本；桌面用户仍会使用云端推理。

核心结果指标建议采用「客户接受并可用于实际工作的交付物数量」。同时跟踪完成一次交付所需的人工作业时间、修改次数、成功率、每次成功交付成本、重复使用率和续费意愿。广告效果变化作为业务观察，不在未做对照验证时直接归因给 Agent。

首期范围、阶段验收及试点方法见 [MVP 与验证计划](02-mvp-and-validation.md)；技术依据、网关验证项和待确认问题见 [调研与决策记录](03-technical-findings-and-open-questions.md)。
