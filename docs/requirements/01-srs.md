## 3. 业务规则与边界

任务接受与业务完成是不同事件；技术执行成功后，用户可以接受或要求修改产物，不能修改历史运行记录来模拟重做。

同一品牌不同项目可共享经授权的资料；企业之间不共享默认记忆。所有计算先确定账户、币种、时区与口径，再生成说明。AI 生成文案不参与金额或权限的权威判定。

首期可先开展导入型试点，但正式连接器、扩展、完整 Desktop、生成式视频、SEO/GEO 和企业自动化仍保留在完整范围内。是否独占云电脑是资源和产品决策，不改变云端持续执行目标。

Web 的完整对象、交互和跨端边界以 [Web 工作台需求](../product/05-web-agent-workbench.md) 为准。此前关于“固定一个 Agent、多专业协作远期后置、云文件需独占云环境”的理解已被替换；本轮 CORE01 将内核收敛为 Codex，内部 AI API 与三端要求继续作为硬约束。

## 4. 完成判断

CORE01 为用户最新指定唯一使用 Codex 的指令，细化已有 REQ-044/075，不新增同义需求。约束覆盖默认助手、角色、团队与计划任务，以及发布、实例化、启动和恢复；对应 TC-044/075 验证版本固定、非 Codex 配置拒绝及禁止自动内核回退。具体集成见 [Codex 分册](../technical/02-runtime-and-ai-gateway.md)。

BRAND01 为用户指定官网作为最终产品视觉依据的指令，REQ-081/082 是其设计与验收拆分。颜色、字体、组件及三端规则以 [品牌规范](../product/07-brand-design-system.md) 为准，取样证据见 [官网核查](../research/03-copypaste-brand-reference.md)。旧通用配色由该规范替代。

每条需求依次经过：设计覆盖 → 接口/数据准备 → 实现 → 测试证据 → 试点接受。当前交付覆盖前两项的文档与契约；后续实现状态单独记录，不以本文件中存在条目判为实现完成。
