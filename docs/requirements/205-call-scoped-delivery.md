# 逐次交付状态 / Call-scoped delivery

本补充保留原 102 条需求与 32 组验收范围，修正 REQ-008/009/011/019/021/035/039/043/046/058/068/078 的相关交付判定，不代表这些需求已完整验收。

1. 同一工具的不同调用属于独立输出。另一份图表、图片或文件成功，不得清除原失败项。
2. 仅服务器已经确认“未执行且可修正”的失败，才可在原工作、原权限和原预算内修正。修正须携带该任务、同工具的精确失败参考号；不能把参考号作为权限、费用确认或预算增加。
3. 修正再次失败，保留原义务；结果未知时转为核对原操作，不能自动重新生成或投递。已发生费用、已完成文件和原始账目保持。
4. 输入等待、后续原生回合和活动日志到期清理，均不能消除尚未解决的交付项。结束判定须读取独立持久状态。
5. 音频与生成视频必须确认原任务完成、交付可用、实际文件和确定用量。仅返回任务记录、失败状态、取消状态或被阻止的文件，不算交付成功。语音须含音频，转写须含原稿和两种字幕。
6. Web 与共享 Desktop 成果界面显示逐项失败及安全支援号；活动流与原生分页使用一致的记录身份。完整本机操作、全部业务质量和生产长期矩阵仍按原始范围验收。
7. 修正参考号填错时，保留已有待处理项并允许核对后重新修正；不得制造永远无法解除的额外成果义务。结果未知的原操作不能因重复调用身份或换参数而变成可自动重做。

Independent calls of the same tool represent separate output obligations. Only an explicitly linked correction of an unresolved, server-confirmed not-performed validation failure may resolve that obligation. Task identity, registered tool, authorization, original budget and actual completion remain mandatory. Unknown operations require their original receipts; recorded costs and real partial files remain intact.

Durable metadata survives new native turns, customer input waits and activity pruning. Audio/video completion requires confirmed usage and actual available deliverables; returning a failed, cancelled or blocked job is not delivery. Current increments do not replace the original professional, operational or full native acceptance matrices.

Mistyped correction metadata preserves the original obligation and can be corrected without a phantom output. Unknown original operations remain unknown across duplicate identities and changed arguments; status and receipt checks do not create replacement operations.
