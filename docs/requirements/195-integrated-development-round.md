# 195 · 整轮开发与统一验证

本轮遵守用户新增顺序：先完成整轮待办的代码与文档，再统一构建、测试、联调、调试和发布。开发阶段不按单模块执行测试；测试失败统一进入本轮修复批次，再统一复验。

本轮开发包：

1. Web / Desktop 统一输入：拖入、剪贴板图片、固定版本项目引用、上传状态、明确的新工作与费用语义，以及作用域/会话切换后的清理。
2. Web / Desktop 任务成果工作区：任务内成果、文件预览、活动、费用及继续修改，键盘切换、长内容与移动布局。
3. 后台运行就绪面板：真实模型、Google/Meta、邮件、原生运行器、Office、存储及生产配置的准确状态和配置路径，不返回密钥。
4. 角色专业验收台账：绑定实际任务、模板/内核/技能及交付快照，区分正常、修改、异常及人工评审；不能用静态数量自动授予专业资格。
5. Linux Office 原生转换：独立临时配置、禁用宏/外链、运行时校验、超时终止和清理，不使用 Docker/WSL。
6. Extension 输入完善：剪贴板图片、拖入反馈与权限/上传状态；保留原生右侧栏和云端执行。
7. 通用体验收口：可见焦点、正确的弹层回焦与键盘操作、主题/长内容/缩放、状态反馈及减少首次必填。
8. 整轮交付：六端独立构建与版本对应、双语 README、实际截图与交互记录、原生统一验证脚本、部署回滚和普通 Git 同步。

194 的32组敞口全部纳入本轮追溯。01–06真实视频/音频/Google/Meta须公司外部配置，不以假服务宣布已接通；08/09/10/11/12/13/28专业质量与业务效果须实际交付评审；14–23/25–27/31/32中的完整组合、长期可用性和灾备数字须有对应测试或演练，不用实现完成替代验收。07、24、29、30及相关输入/管理代码在上述开发包处理。
