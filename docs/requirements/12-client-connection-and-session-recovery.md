# 四端连接异常及登录失效处理

承接原始 REQ-003 登录与会话、REQ-035 Web工作台、REQ-036 扩展网页协作、REQ-039 Desktop、REQ-048／098 后台使用体验和 REQ-060 源码交付。本补充明确异常时的客户可见行为，不增加新的收费、登录方式或管理员权限。

| 编号 | 约束 | 可见结果 |
| --- | --- | --- |
| CLIENT-ERR-01 | 读取请求无法连线 | 使用当前繁中／英文说明如何恢复；保留有效登录。 |
| CLIENT-ERR-02 | 提交请求的响应丢失或无法解析 | 明确提示结果未确认，先查收结果；应用层不自动再次提交；浏览器底层重传继续使用原编号，由服务端去重。 |
| CLIENT-ERR-03 | 原有固定请求恢复 | 客服授权沿用原编号、范围及期限；扩展沿用原委派的消息编号，不新增第二个任务。 |
| CLIENT-ERR-04 | HTTP 401 的判断独立于正文格式 | 即使正文为空或网页格式，当前登录也应失效；隐藏旧工作区及受保护内容。 |
| CLIENT-ERR-05 | 迟到请求属于旧登录 | 拒绝旧结果，不能清除新登录或覆盖新登录的防伪标记。 |
| CLIENT-ERR-06 | 客户端主动取消请求 | 保留取消语义，不能误报为需要重试的连接错误。 |
| CLIENT-ERR-07 | 内部技术错误与翻译 | 已知连接异常不直接显示原生运行时、响应正文、密钥、地址或堆栈；切换语言后更新同一提示；扩展后台轮询不清掉未确认提交提醒，高级工具面板不能遮住提示。 |
| CLIENT-ERR-08 | 恢复后的页面状态 | 管理后台列表成功刷新后清除该列表的旧连接提示，其他表单错误独立保留。 |
| CLIENT-ERR-09 | 现有端形态 | Desktop继续使用本机Codex及用户单独授予的本机权限；Extension继续使用原生右侧栏和云端Agent。 |
| CLIENT-ERR-10 | 可交付的验证入口 | 各端保持独立源码库；当前交付源码严格编译，历史执行原件保持原字节且不冒充当前入口。 |

这组定向检查不能关闭完整企业身份接入、所有会话竞争、全部运营页面或全平台无障碍验收。业务继续使用用户授权的假数据，正式模型及第三方服务仍按原需求跟踪。
