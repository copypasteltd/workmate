# 原生备份与恢复要求

本项落实已有的数据可恢复性、不可逆删除和外部操作核对要求。RPO 15 分钟、RTO 4 小时、备份滚动保留 35 天仍是原验收目标；本地隔离演练的时间不能直接视为正式环境服务承诺。

部署负责人可以运行原生命令，在线取得同一 PostgreSQL 快照内的业务数据、账本、授权、对象引用与删除记录，并保存这些引用对应的确切文件。已封存的预算操作回执随备份保留。所有备份内容使用独立备份密钥加密，数据加密主密钥由部署负责人另行保管。

删除日志必须能独立导出并保存在备份之外的故障域。恢复旧备份时要求提供同一来源、覆盖时间不早于备份快照的删除日志，重新应用内容删除与对象抑制。界面明确显示日志与故障时间的差距，不能把缺失的时间窗口标作已覆盖。

恢复只允许新建专用数据库与新建数据目录，校验失败保留可诊断的隔离状态。恢复环境默认禁止用户端、管理端和 worker 接入；任务、媒体生成、退款和广告变更不自动重播。恢复过程中不改写既有金融事实来制造对账成功。

Admin 提供独立的全局恢复可见权限，要求当前 MFA。展示最近有效备份、删除日志、恢复演练、摘要、时间差和结果，并支持筛选、分页与详情。路径、密钥、数据库连接信息和存档正文不进入该接口。已有管理员授权通过明确升级后使用新权限。

本项的可运行操作、配置、数据边界与验证材料见 [实现说明](../technical/114-native-backup-recovery.md)。
