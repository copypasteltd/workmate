# Desktop 本机专家团队 / Native specialist teams

本项补充团队协作和 Desktop 本机执行要求，不改变 Codex 唯一内核、公司统一 AI 网关、原有 18 个预设角色、Web／Extension 云端执行及全部原始验收范围。实现和本轮实测范围以阶段139的技术说明、检查点和编号清单为准。

## 客户流程

1. 在 Desktop 的「本机团队」选择已保存团队，或创建协调员和成员。协调员使用通用助手，成员选用已安装的固定版本专家；团队定义可修订和归档，旧运行保留原成员版本。流程顾问继续走独立流程，不在团队步骤里嵌套另一套流程。
2. 填写整体目标、各步要求、前置步骤、每步预算、协调员预算及并行数。最多16步、3步并行、7位成员及1位协调员。同一成员可承担多个独立步骤。
3. 审阅时在原生文件窗口选择本机目录，并明确授予只读、目录读写或完整本机权限。审阅不调用 AI、不占用资金；展示固定目录、成员／Skill版本、依赖、权限和总预算上限。
4. 确认后，各成员在客户电脑以独立 Codex 会话工作，共用已批准的目录。独立步骤可并行，依赖步骤只能读取已完成的获准前置成果。协调员须等全部成员及其媒体交付结束后才能开始。
5. 运行页展示成员进度、当前预留和实际消耗，打开对应本机会话可回答工作问题、查看工具记录和成果。团队会话只执行已批准的分工；新增要求需重新审阅，不允许绕过原图及预算任意追加工作。
6. 完成后下载团队包，包含协调员、各成员已提交的结果文字及固定文件版本，附中英说明、清单和校验和。本机未提交文件仍保存在客户电脑；下载不调用 AI、不执行包内代码。
7. 可停止整组工作、从任一成员撤销整组本机权限，或在断线后继续原受理。已接受但结果未知的本机操作不能自动重跑；只同步原回执并保留费用核对状态。

## 权限与费用约束

- 团队定义属于项目；运行和其对话属于发起人的私有内容。另一成员即使在同项目也不能读其私有运行。所有读、导出和工具操作继续校验当前项目权限、来源状态和保留期。
- 运行固定用户、登录族、设备、工作目录摘要、本地会话、Codex版本和程序摘要。任何成员不得换目录、换设备或修改固定图；Desktop任务不得进入云端任务队列。
- 完整权限由客户在本机窗口主动授予，遵守当前 Windows 用户权限；服务端、网页及团队成员结果不能替客户授予、扩大或恢复本机权限。成员输出属于不可信资料。
- 每步按实际公司网关记录结算。协调员在受理时预留、等待时不推理；成员依赖就绪且余额及套餐容量允许时才受理。总额不得超出已批准图的各步预算之和。取消释放未执行预留，实际费用保留，未知请求保留核对。
- 停止／撤权首先中断本机执行，不依赖服务端网络恢复；服务器收回后续派工及推理授权。未收到公司的取消回执时明确显示待同步，不能标为已结清。
- 登录撤销、项目归档、账号停用、内容撤回或运行到期，由公司清理流程取消未受理后续步骤；不能借清理流程启动云端替代执行。
- 并行成员共享客户所选目录。客户应将并行步骤分配到不同文件；本阶段不承诺多个进程同时编辑同一文件时自动解决语义冲突。

## 验收边界

检查包含实际原生数据库迁移、身份／授权／预算约束、并行及依赖、本机持久回执、停止及撤权、固定版本 ZIP，以及打包 Desktop 的真实 Codex 和本机文件操作。业务内容、模型答复及原生选择窗口的决定继续使用明确假数据。正式公司模型质量、签名安装矩阵、跨机器工程恢复、所有专业角色与全部异常组合保持独立验收，不以团队定向检查替代。

## English

Desktop teams run separate Codex sessions on the customer's computer. A review freezes specialist versions, dependency graph, per-step budgets, device, login family, local folder and pinned runtime. Review is free; admission reserves only approved task allocations. Up to16 steps and3 concurrent members are supported, followed by an assistant coordinator after all member deliveries finish.

The native permission dialog controls read-only, workspace-write or full local access. A team shares its approved folder and permission, with distinct durable member sessions. Stop or revoke affects the entire team. Lost responses recover the original admission or saved outcome; an unknown accepted native operation is never replayed. Native tasks never enter the cloud queue.

The private run page shows progress, holds and actual charges. Its team archive contains exact submitted member and coordinator outputs, bilingual instructions and checksums. Local-only files remain local. Exporting makes no AI call. Web and Extension keep their existing cloud execution flow. Production models, professional output quality, signed installation coverage and portable project recovery retain their original acceptance requirements.
