# 首期范围、阶段验收与试点验证

> 历史来源说明：本文件保留第一轮需求梳理。现行完整规格、接口、阶段和验收以 [文档总目录](README.md) 中的分册为准。

> 内核方向修正：CORE01 已固定使用 Codex，M0 和 G01 改为 Codex 集成验证；其他早期范围仍以新版分册为准。

版本：v0.1（建议方案，待范围确认）  
日期：2026-10-18  
上游：[产品需求](01-product-requirements.md)。本稿定义后续应做的验证，本轮尚未执行内部接口或产品测试。

## 1. 首期建议

首批用户已确定为现有客户的 marketing 团队。建议先用云端 Web 交付两条完整业务流程：

1. **素材生产**：品牌资料和活动 brief → 广告图及可修改文字排版 → 多语言、多尺寸素材包；同时验证一种固定模板的短视频成片。
2. **营销复盘**：上传或连接广告数据 → 确定性计算 → 有证据的分析报告 → 下一轮素材测试 brief。

企业重复流程优先从这两条流程中抽取。扩展和桌面端进入后续阶段；如果试点明确以本地目录监听为主要痛点，可提前本地执行器验证，调整顺序。

视频属于高优先级业务。建议先交付可控的模板成片，把生成式视频、复杂修复和高级特效逐项加入。图片生成仍需真实图片能力接入；不能用文本模型输出提示词来视为生图交付完成。

## 3. 首期暂不纳入的范围

以下均为范围建议，仍保留在长期需求池：

- 三端同时完整发布、所有桌面系统同时支持。
- 开放式自动控制任意桌面程序、任意网站或整个本地磁盘。
- 一次接入 Meta 的广告、自然内容、私信、线索及全部运营功能。
- 无需人工策略和评估的自动投放、自动调整预算。
- 覆盖所有模型和消费级 AI 搜索产品的 GEO 观测。
- 任意高级视频特效、完整字体家族生成及所有专业设计工程格式。
- 客户自带第三方 AI Key 绕过内部网关的使用路径。

## 4. 阶段与进入条件

不在团队规模、预算和接口条件未知时给出固定周数。建议按以下完成条件估算排期。

| 阶段 | 主要工作 | 离开本阶段需要的证据 |
| --- | --- | --- |
| M0：能力与样例验证 | 明确网关协议；验证固定 Codex 的 app-server 集成；打通生图、模板视频、数据计算最小路径 | 同一组真实样例有实际文件和运行记录；Codex 与关键依赖有明确结果 |
| M1：Web 导入型试点 | 品牌资料、素材包、模板成片、数据导入、可核查报告及任务中心 | 客户在真实工作中试用；记录接受率、人工时间和完整任务成本 |
| M2：连接器型 Web MVP | 完成首个平台正式授权与同步、异常恢复、成员权限和额度 | F01–F12 全部通过；试点客户能重复完成两条主流程 |
| M3：浏览器与本地能力 | 扩展、必要的本地桥接、一个操作系统上的目录任务 | 浏览器和设备离线、权限撤销、资源清理等场景通过 |
| M4：完整桌面和流程扩展 | 桌面工作台、更多连接器、定时任务及企业流程 | 客户新增价值覆盖相应支持成本，具备明确交付标准 |

CORE01 已固定唯一使用 Codex。M0 验证其固定版本、内部网关、工具与业务样例，不再安排内核比较或替换；未通过的能力修复后重新验收。当前完整实施范围以新版 [开发指南](technical/08-development-and-delivery.md) 为准。

| 门槛 | 验证内容 | 未通过时的处理 |

## 6. 业务验收样例

以下规格用于建立固定验收样本，均可随试点资料调整，不是套餐承诺。

### A01：品牌广告图交付

给定一套品牌资料、商品素材和一份 brief，要求三套创意、繁中和英文两种语言、三种固定尺寸，共 18 张输出。

验收实际文件、尺寸、文字准确性、Logo、字体和品牌色；能够从产物回到任务及资料版本。用户只修改促销文案时，已有图片素材可复用。失败的某个尺寸有明确状态，不把整批误报为成功。

### A02：模板短视频交付

给定已授权素材、固定文字和音乐，输出一条示例为 15 秒、9:16 的短视频。

验收可播放的实际视频、约定分辨率和时长、字幕准确性、文字安全区、音画配合及模板重用。更改字幕后可以重新导出。记录渲染与媒体费用；如使用 AI 配音，其请求也走内部服务。

### A03：营销数据复盘

给定 Google 和 Meta 导出样例，以及人工核算结果，生成指定日期范围的复盘报告。

验收汇总金额、曝光、点击、CTR、CPC、CPA 与适用的 ROAS；每个指标均回到来源。专门包含零点击、多币种、重复行、缺少转化数据及两个平台归因重叠的样本。报告区分已知事实与待验证解释，缺失数据不得补造。

### A04：跨流程复用

从 A03 的结论创建下一轮素材测试 brief，再用同一品牌资料生成新版本。

验收活动、素材和报告间的关联；只有证据支持的内容被写为事实；创意建议保留其假设属性。投放 ID 尚未映射时可由用户补充，不靠文件名猜测为确定匹配。

### A05：长任务、恢复与取消

任务被云端接受后关闭页面，再次进入时可查询真实状态和产物。验证排队取消、运行中取消、内部 API 超时及部分媒体任务失败。

验收已保存的状态、部分产物及费用；重试能够识别已完成步骤。上游不支持立即取消时，应说明当前状态与可能继续发生的用量。

### A06：授权与资源边界

企业 A 的成员尝试访问企业 B 的任务、素材和连接器，应被服务端拒绝。撤销平台或目录授权后，新操作应停止使用该授权。验证所有 AI 请求的去向以及工具中是否存在直连供应商路径。

未来引入浏览器执行时，验证任务成功、失败和取消都能清理不用的标签页和会话；不关闭用户原有工作页面。

### A07：本地能力（M3 验收）

授权一个目录，执行批量处理和结果写回；验证访问范围外路径、写入撤销、设备离线、断线恢复和重复任务。

验收只能处理授权范围；设备离线显示等待；恢复后不重复覆盖或提交。安装与运行采用本机原生路径，不调度本地 Docker 或 WSL。

## 7. 试点方法与指标

建议先选择少量现有 marketing 客户，每家采集一项高频素材任务和一项高频分析任务。确认是否允许使用真实资料；必要时先脱敏，再保留可核算的测试样例。

对每项任务记录原有流程、参与人员、人工时间、输入、期望交付、实际修改、最终接受结果与费用。相同任务规格下比较变化，避免将不同复杂度的任务直接对比。

| 指标 | 统计定义 | 首期使用方式 |
| --- | --- | --- |
| 可用交付率 | 客户接受并可用于实际工作的任务数 / 已提交且具备必要输入的任务数 | 与技术完成率分别统计 |
| 人工时间 | 用户补资料、检查、修改和整理交付花费的总时间 | 与原有流程比较，计入返工 |
| 每次成功交付成本 | 同一统计范围内全部相关执行成本 / 可用交付次数 | 计入失败、重试和未被接受的变体 |
| 报告可核算性 | 抽查数字能否用其数据快照与计算口径复现 | 固定验收样例应全部一致 |
| 等待与处理时长 | 从任务接受到首个状态、首份产物及最终完成的时间 | 分别记录排队与执行的 P50 / P95 |
| 重复使用 | 客户是否在后续真实任务中再次使用同一能力或模板 | 判断工作流价值与保留意愿 |
| 商业意愿 | 愿意继续使用、付费或购买接入服务的证据 | 与口头满意分开记录 |

接受率、节省时间和成本上限的数值目标，在取得人工基线与内部单价后确定。此时不作生产 SLA、广告回报提升或固定生成速度承诺。

## 8. 费用与商业验证

每次任务的成本至少包括语言模型、图片或视频、其他 AI 能力、执行算力、存储与下载流量，以及可归属的第三方工具费用。内部网关实际单价作为计算依据，不能直接套用公开模型报价。

商业毛利评估还应计入接入、客服、人工修订、支付和持续维护成本。视频、批量素材及高推理强度任务应单独观察，避免只看 token 费用。

建议验证：企业基础费用覆盖常规使用与支持；媒体和高资源能力采用明确额度或用量计费；定制接入及流程建设单独定价。费用方案与三端的安装形态分开设计。

## 9. 首期范围冻结需要的信息

1. 试点客户最常做的三类素材，必须交付的文件格式、数量、语言和视频规格。
2. 客户广告支出主要在哪个平台，是否已有可用账户授权与 GA4 / Search Console 数据。
3. 内部网关准确模型标识、协议能力、媒体接口、限额及单价。
4. 试点是否必须有本地目录能力，主要操作系统以及能否安装本地组件。
5. 可投入团队、预算、目标试点时间和首期收费意向。

这些信息用于后续编写可估时的开发任务和正式验收范围，不影响本轮需求梳理交付。
