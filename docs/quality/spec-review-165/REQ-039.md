## 4. 已反驳的候选

1. **“Desktop 首页仍在云执行”排除。** 实际路由、native IPC、固定本机 exe spawn 连成一条路径；普通公司业务页面共享外观并不证明 Agent 循环在云。
2. **“fully permission 仍只给一个目录一小时/只写新文件”排除。** 一小时 grant 属 files bridge；native Agent 的授权和 danger-full-access 是另一条路径，native grant 不使用一小时时效。
3. **“full 模式仍禁 shell 或逐命令弹窗”排除。** 原生配置 shell=true，full policy never，thread 返回配置核对；只读 GEO 隔离模式是明确独立用途，不是客户 full mode 降级。
4. **“卸载直接删除，没停 native”排除。** NSIS → --prepare-uninstall → durable removal → signOut/invalidate/close 以及失败中止删除均有实际调用。
5. **“没做签名更新，所以本轮必须补实现”排除。** 有 manifest、hash、Authenticode 与 native helper 实现，当前 unsigned candidate 是授权范围。实际签名安装/升级验收仍不可据源码宣称完成。

父任务已定位 Desktop/Web 首次建企业请求未知后换 key 的问题（Desktop `renderer/src/main.tsx:526` 附近）。该问题可能影响本机旅程到达工作台，属于父任务正在独立审查和修复的 onboarding 条款，不是本报告新发现；本文没有验证该问题或把尚未构建补丁计入 rc.4。
