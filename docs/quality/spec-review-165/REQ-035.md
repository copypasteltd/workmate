可复现时序（静态代码推导，未声称本次实际执行）：

1. Fresh signed-in user submits the two required names at /welcome; post() generates K1.
2. POST transaction commits T1, owner membership, wallet W1, project P1 and replay(actor,tenant.create,K1).
3. Lose the response after commit, or deliver unreadable JSON: client reports CLIENT_RESULT_UNCONFIRMED before local selection is written.
4. AsyncForm clears busy; Onboarding retains no original body/key/result and allows the unchanged form to be submitted again.
5. Second click generates K2. replay does not match K1, so it creates T2/P2/W2. User enters second result instead of recovering T1/P1.
6. Refreshing /welcome also retains no original creation attempt. Existing memberships do not close this form; intentional additional-workspace creation remains a supported entry.

同键重放、错误正文 409、已删除回执 410 都已有实现；客户端换了新键，使这些保护无从触发。不是“后端没有幂等”，也没有证据证明付费任务或扣费重复。首次云端任务的持久化提交机制是相反的正面证据。

实际路由是 `/welcome`，没有 `/onboarding`。已有企业但没有可访问项目时，`main.tsx:L914-L925` 提供主动创建工作区入口；`L522-L523` 允许所有已登录用户使用此表单。因此不能用“membership 非空就跳走”消除合法的第二企业创建。需在发送前持久化账号绑定的原正文/键，未知结果恢复同一请求，刷新后保留，账号变化限制旧选择写入；可新增专门的企业创建回执。`admin-support.ts:L486-L505` 是支持授权业务专用，不能直接用于企业创建。
