## 1. 共用与差异

Web 提供完整云端工作区；Chrome 扩展提供 ChatGPT 式对话原生右侧栏，获取、读取并上传用户获选文件，由云端 Codex 执行；Desktop 必须在客户本机运行 Codex Agent，支持客户主动授予完整本机权限，操作能力对标 Codex Desktop。详见当前硬约束 [CLIENT01](../requirements/03-client-execution-amendment.md)。品牌、身份、业务约定可以共用，执行进程及权限分别实现。

Web 主流程为目标输入、会话中的真实执行、成果预览修改、项目沉淀与持续复用。专业模板、技能、团队和基础云端自动化是 Web 能力，不能要求用户先安装 Desktop。云文件与获准本机文件分开显示；三端一致指身份、方法和业务记录一致，不暗示每端能执行所有本机程序。

三端共享业务身份及可访问的任务/成果引用，不代表把本机会话无条件迁到云端。关闭 Web/扩展界面不会删除云端任务；Desktop 关闭窗口和退出进程分别处理本机运行。跨端接续重新校验执行位置、设备、本机授权和企业权限，不能从旧缓存恢复已撤销权限。

CORE01 规定所有 Agent 内核均为 Codex；CLIENT01 固定 Web/Extension 云端执行、Desktop 本机执行。Web 与扩展基础流程无需安装 Desktop/Codex，Desktop 由客户端管理锁定的本机内核，不提供内核选择入口。配置与恢复见 [Codex 分册](../technical/02-runtime-and-ai-gateway.md)，当前实现差异见 [方向检查](../technical/69-desktop-local-codex-and-extension-direction.md)。

三端复用版本化品牌 token、真实浅深 Logo、字体层级、按钮/卡片/状态组件。Web 与 Desktop 工作区保留同一视觉，扩展在 360–420px 单栏内重排输入、上下文及成果；原生文件选择器遵守系统规范，Desktop 主窗口使用自绘标题栏和窗口按钮。分别支持浅/深/跟随系统；主题切换保持任务、输入及客户作品不变。实现约定见 [前端设计集成](../technical/10-frontend-design-system.md)。

## 2. Chrome 扩展

Manifest V3 作为设计默认。content script 仅提取用户主动选择的内容；service worker 做来源校验、消息路由和短时操作；side panel 展示会话及进度。所需站点权限按需请求，避免默认全部网站永久访问。

点击扩展图标必须打开 Chrome 原生全局侧栏，参照新版 MetaMask 出现方式；默认右侧，可随浏览器用户偏好位于左侧，不使用 popup 或新标签模拟。切换网页后保留侧栏，初始化不自动打开。具体代码、浏览器限制及运行证据见 [窗口与原生侧栏](../technical/30-native-window-and-browser-sidepanel.md)。

官方文档说明 service worker 可被浏览器回收，因此长期任务在云端或原生执行器中运行；状态保存到受控存储，worker 唤醒后通过游标恢复，不靠全局变量维持任务生命。

网页 → content script → service worker → 产品 API / Native Messaging 的每一跳验证来源和消息 schema。网页无法指定任意原生程序或获取凭证；扩展未安装 host 时仍可提交云任务。

## 3. 原生桥接与配对

桥接组件通过正式安装器注册 Native Messaging host，绑定正式扩展 ID。系统浏览器完成产品登录后，本地显示企业和设备确认，服务器保存 device_id、公钥及能力，本机安全存储 refresh 凭证。

Host 使用 Chrome 规定的消息封包，只传命令、状态和对象引用。大媒体文件不直接塞进单条消息，改用范围化上传 session。设备主动连接产品服务，无需开放任意本地 HTTP 监听或公网端口。

原生执行器与完整 Desktop 共享设备核心，但通过单实例锁和命令账本保证同一 device_id 只有一个领取主体。

## 4. 本地权限与执行

文件桥接的 Grant 由用户在本机选择目录，包含 root 身份、读/写/监听权限、允许项目和过期策略；云端只保存 grant_id 及显示名。此范围适用于扩展可选 Host 和 Desktop 受限文件模式；Desktop 完整本机权限由本机用户另行授予，必须支持本机 Codex 终端及现有文件修改，不能用桥接目录白名单代替。平台数据与计费继续核验企业/项目权限。

文件操作使用相对路径及文件句柄，拒绝绝对路径、`..`、越界 symlink/junction。写回先核对来源内容摘要，文件已被其他程序修改时返回冲突；默认另存新文件，覆盖需具体授权。程序调用使用白名单 executable ID 和参数 schema，不直接拼接 shell 字符串。

监听排除临时文件和本产品输出目录，按文件指纹去重，避免输出再次触发无限循环。休眠、断网和退出时记录检查点；重新在线先同步撤销和任务取消，再领取命令。

## 5. Desktop

设计默认 Electron shell + TypeScript 设备核心，先验证 Windows 原生安装路径，再扩展 macOS。客户端渲染层不拥有 Node/系统权限，通过窄的 preload/IPC 接口访问核心；不把任意模型输出当 IPC 方法执行。

主窗口强制无边框并移除全部 Electron 默认菜单，使用品牌自绘标题栏、拖动区和最小化/最大化/还原/关闭按钮；保留有尺寸约束的缩放。不能只隐藏菜单或套用普通原生标题框。主题、语言、弹窗安全空间与 IPC 来源约束见 [窗口实现细则](../technical/30-native-window-and-browser-sidepanel.md)。

Desktop 在线能力包括本机 Codex 会话、文件读取/修改、终端和已集成工具、Skill、目录任务及媒体处理。客户可选择完整本机权限，也可使用受限模式；实际能力以已集成并验证的工具为准。所有模型 API 仍经内部服务器，断网时不能声称新的推理可离线完成；不会把本机任务静默切到云端。

安装、更新和卸载有签名校验；更新前等待本地步骤检查点并保留恢复信息。卸载撤销设备和 host 注册，提供本地缓存清理选项，不删除用户原有目录。

## 6. 浏览器与进程资源

每个 browser_context、tab、临时文件和子进程记录 owner_task_id、lease、created_at 和 cleanup 状态。结束、失败、取消进入 finally 清理；watchdog 回收失联租约。

默认只回收本任务创建且不再需要的标签页/上下文；用户原有页面保持。若任务需要保留登录会话，保留受控配置和加密状态，不让闲置页面无限占内存。

## 7. 验收边界

分别验证：仅 Web、仅扩展、扩展加 host、完整 Desktop，以及跨端接续。包含 worker 休眠、设备离线、重复命令、授权撤销、路径穿越、写入冲突、升级中断和资源回收。

视觉验收增加两主题、375/768/1024/1440px、繁中英文、键盘/缩放及客户作品原色检查。Web、扩展和 Desktop 分别提交真实代表页面截图，不以本轮静态样板代替客户端运行证据。

命令字段、签名及重放处理见 [本地协议](../technical/05-local-executor-and-browser.md)。全流程不得依赖本地 Docker/WSL，也不自动启动这些环境。

## 8. 后台变更跨端生效

REQ-085/100/102 要求账号冻结、权限撤销、VIP/额度变化和内容隔离在新 API、工具、worker、下载及三端显示中保持一致。推送用于刷新 UI，权威版本与有效时间决定能否执行；离线设备重连先同步撤销、取消及权益摘要，再领取命令。Admin 不因平台权限获得用户本机目录或原生授权，设备撤销走相同设备核心。后台详情与传播规则见 [Admin 分册](../technical/11-admin-control-plane.md)。
