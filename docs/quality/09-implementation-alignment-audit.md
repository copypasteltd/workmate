# 全体系需求差异复查与修复

范围保持 SRS 的全部 REQ-001–102、同号 TC、NFR、G01–G10、机器契约和四个客户端；不会将既有 0.5.0 试点范围改写为完整需求。用户于 2026-10-19 指示「暂时先用假数据」，因此本轮允许明确标识的本机模拟网关与业务数据进行功能/故障验证，真实服务准入资格另行记录。

## 基线与证据标准

[102 条逐项基线](requirements-alignment-baseline.json) 保存需求原文、完整验收条件、初步差异、源码候选及独立仓库版本。此表是修复起点，不是通过报告。单纯文件存在、页面可访问、编译通过或相近路由存在均不能关闭一条需求；需要与该条条件相符的实际运行证据。

初始规范有 221 个操作，0.5.0 实际清单有 167 个 method/path。将参数名规范化后，190 个规范操作没有相同 method/path；部分为嵌套路径/认证载荷差异，部分为尚未实现功能，不能把 190 解释为 190 个完全缺失业务。已匹配的路径也仍须验证字段、状态码、分页、错误和事件。契约对齐须保留现有客户端兼容，并逐步使规范接口真实可用。

## 当前修复顺序

1. 数据与执行基础：物理删除/运行缓存/可查询作业、上传校验和恢复、持久事件、检查点及权限复查。
2. 产品主路径：云文件树、依赖补齐、项目继承、技能生命周期、成果审阅/继续工作和站内通知。
3. 业务闭环：批量设计/视频/音频、广告同步/SEO/GEO、角色正常/修改/异常验收、专业团队与统一预算。
4. 后台与各端：完整资源治理、限时用户视图、异步批量/导出、模型配置发布、原生目录监听/更新和跨端撤销。
5. 兼容与验证：逐项规范契约、两主题/语言/尺寸/键盘、负载、备份恢复及完整验收条件复查。

每个改动仍按唯一 D 盘根目录、dev 源码、docs 主文档、独立 Git、原生工具及自建浏览器清理约束执行。需要外部采购、生产密钥或签名证书的门槛不通过伪造证据关闭；假数据只改变当前测试依赖，不删减功能目标。
