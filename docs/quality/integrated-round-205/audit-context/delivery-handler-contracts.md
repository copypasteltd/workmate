# All twelve delivery-tool handler return contracts

Scope is the `deliveryTools` set at `dev/copypaste-platform/src/runtime-tool-feedback.ts` L87. Every row describes code that was read; no invocation was executed. A returned file is not a professional/customer acceptance finding.

All cloud tool resolves enter `runtimeToolContent`, emit completed and clear one same-name failure (`runtime.ts` L489-L493). `runtimeToolContent` serializes the value or accepts only a trusted `RuntimeImageResult` instance for image content; it does not classify domain state (`runtime-tool-content.ts` L5-L16).

## Shared persistence and replay

The transactional wrapper first authorizes/locks, validates input, then uses actor+task+native-call replay and optional exact-input cross-attempt reuse (`task-business-tools.ts` L224-L264). `Database.tx` commits before resolving and rolls back on any thrown error (`db.ts` L24-L63). `saveAsset` hashes bytes, writes immutable storage and inserts the version/artifact event in the caller's transaction; storage objects may remain unreferenced if that transaction rolls back (`storage.ts` L310-L317, L438-L466).

`replay` obtains an advisory transaction lock, rejects changed or erased replay identities, executes only when no saved result exists, and stores the serialized result after the effect succeeds (`access.ts` L99-L137). Cross-attempt reuse also checks all referenced output versions remain available (`task-tool-reuse.ts` L23-L104). Image/audio/video use their own durable operation lifecycles in addition to the generic runtime event layer, as described above.

## Explicit limits of this reading

Third-party Codex/model behavior, storage provider guarantees, FFmpeg, PDF/PPTX consumers and professional design quality are external behavior. This record follows their local boundaries and inspected return contracts; it does not prove those external implementations or run real jobs.
