## 1. 定位与业务目标

为在港企业提供持续可委派的 Agent 服务，包含云端入口与本机完整客户端。Web 产品形态为企业云端 Agent 工作台：用户描述工作目标，Agent 使用获准的资料与能力执行，交付可检查、可修改、可复用的成果。首批为现有客户的 marketing 团队，深入支持「品牌素材生产—效果复盘—下一轮测试」循环，并承载企业重复工作。

首期目标是减少资料重复整理、素材返工和人工报表时间，获得可重复使用及付费的证据。持续 Agent 有稳定职责与资料，任务是每次具体委派，会话承载沟通；三者分别建模。

## 2. 人群与工作机会

| 人群 | 高频问题 | 产品应交付 |
| --- | --- | --- |
| marketing 执行人员 | 反复找品牌资料、改文案、适配尺寸 | 复用资料且可修改的多版本素材包 |
| 投放分析人员 | 多平台报表口径杂乱、结论难核查 | 数字可复现、证据可查看的复盘 |
| marketing 负责人 | 不清楚任务进展、质量与成本 | 可审阅的产物、历史和额度 |
| 企业管理员 | 授权分散、设备和资料难管理 | 项目权限、连接状态、设备撤销及用量 |

代理商多客户代运营、其他企业部门是扩展方向。首期一个企业可有多个品牌，避免将品牌与企业身份混为一体。

## 3. 产品结构

统一工作区以新工作、项目、会话、Agent 与团队、能力中心、资料成果和自动化组织。用户直接输入目标并附资料，进入会话执行与右侧成果面板；品牌、平台授权与长期配置随实际工作渐进补充。业务类型通过示例、专业模板、技能和结果视图表达。

Web 提供完整云端业务入口；Chrome 扩展在原生右侧侧栏提供 ChatGPT 式连续对话、附件获取/读取/上传，Agent 在云端执行；Desktop 在客户本机运行 Codex Agent，提供文件、终端、Skill 和本机工具操作，并允许客户主动授予完整本机权限，操作能力以 Codex Desktop 为对标。三端共用内部 AI 服务及平台业务控制，不能把 Desktop 实现为云端执行加文件桥接。详见用户已明确的 [CLIENT01](../requirements/03-client-execution-amendment.md)。

CORE01 固定 Codex 为唯一 Agent 内核，默认助手、所有专业角色、企业定制、团队和后台计划统一使用。产品层管理任务、权限、资料和计费，Codex 通过受控集成执行；所有 AI 继续经公司内部服务器。内核不是客户可切换的配置项，故障按既有恢复规则处理。集成与版本约束见 [Codex 技术设计](../technical/02-runtime-and-ai-gateway.md)。

最终视觉沿用公司 [CopyPaste 官网](https://copypaste.hk/) 的配色、真实 Logo、衬线展示标题、无衬线正文、胶囊按钮及细边圆角卡片；浅深主题与组件跨三端复用。品牌规则见 [设计规范](07-brand-design-system.md)，同一平台中的开发、设计、营销和流程角色使用一致视觉。客户交付作品按客户品牌及 brief 制作。

提供开箱即用的默认助手及预置专业 Agent 模板；角色版至少 12 个通过真实验收的可用角色，覆盖软件开发和设计，包含 Codex＋设计 Skill＋Image 2 的「设计师」。本次定义 18 个角色，每个包含技能、工具、输入输出、工作步骤及交付标准，支持创建、复制、配置技能与资料范围。一个 Agent 可服务多个独立会话；一个会话可推进多个具体任务。复杂工作使用有协调者和专业成员的 Agent Group，与内核后台临时子任务分别建模。

项目持续沉淀资料、工作标准、技能版本和获准连接；能力中心区分专业角色、Skill、工具、连接器和解决方案包。从一次已接受工作可以保存方法、交给同事复用，或创建云端计划。完整交互见 [Web 工作台](05-web-agent-workbench.md)，对标事实与推导见 [WorkBuddy / Accio 研究](../research/01-web-benchmark-workbuddy-accio.md)。

## 4. 三条完整价值链

### 4.1 创意生产

输入 brief 与现有资料 → 按需补品牌和必要事实 → 列出交付矩阵与费用范围 → 制作 → 在会话旁预览、选区反馈与修改 → 接受、导出并存入项目。产物包含实际图片/视频、版本清单和可恢复编辑描述；准确文字与背景图分层处理。

生成式视频和高级特效按能力逐项开放。首期模板视频必须真实成片；仅有脚本或提示词时准确显示其交付类型。

### 4.2 效果复盘

选择平台或上传报表 → 确认字段与口径 → 获取快照 → 计算 → 查看证据报告 → 转为下一轮素材测试。不同平台的转化和币种保持可识别，缺失数据影响结论，不由模型补齐。

### 4.3 重复工作

在对话中提出重复需求，或从成功任务保存方法 → 确认输入输出、执行角色、授权与预算 → 手动复用 → 可选云端定时/事件触发 → 检查每次交付和异常。用户无需先编排完整流程图；稳定方法可沉淀为技能、解决方案包或结构化流程，再供团队复用。

## 5. 业务接受与产品质量

执行结果记录四种业务评价：待审阅、已接受、需修改、已弃用。评价与任务技术状态分开，接受后修改会创建新版本或新任务。

素材验收关注文字、品牌、尺寸、商品准确性及可编辑性；报告验收关注口径、数字、来源和建议；流程验收关注持续可复用及失败可恢复。核心指标是实际可用交付，不以消息数或生成次数作为价值替代。

## 6. 首期与完整范围

M1 完成 Web 工作台与导入型业务试点，包括会话、专业模板、技能绑定、云文件、成果迭代和工作模式，同时交付可运营的 Admin 基础：用户与企业、消耗钻取、人工费用和 VIP、内容与任务控制、权限和审计。M2 补齐共享项目能力、专业团队、基础云端计划、首个正式广告连接器及完整后台批量、导出和用户端目录发布。M3 交付扩展及原生文件桥接，M4 交付完整 Desktop、更多连接器、生成式媒体、SEO/GEO 和更丰富的企业流程。完整功能及阶段见 [SRS](../requirements/01-srs.md) 和 [发布计划](04-release-and-commercial-model.md)。

长期独占云电脑、实时电脑画面、自动投放和更多企业系统按同一架构演进。逻辑云文件持久化不依赖独占云电脑；专业团队协作纳入 Web M2 设计。阶段是建议基线，未承诺人力、日期或尚未实测的外部能力。

## 7. 关键产品规则

- 关键字段采用渐进补充，已授权范围内的读取和可逆处理连续执行。
- 发布、改预算和敏感覆盖按照具体操作授权；长任务不因缺少无关偏好而反复中断。
- 每次媒体调用之前检查能力和预算；用户看得到预计范围、费用累计及最终结算状态。
- 本地文件「留在电脑」与「内容用于云端推理」分别说明；不作不准确的数据驻留宣称。
- 用户关闭 Web/扩展界面后，云端工作继续；Desktop 本机工作的关闭、后台运行和退出分别显示真实状态，设备离线不自动转成云端执行。
- 默认执行，按需选择先计划或仅咨询；计划确认固定版本，不能替代资源授权。
- 技能安装、启用、绑定、资源权限与能力可用性分别判定；团队共享不会自动暴露个人记忆、会话或凭证。

## 8. 成功指标与试点

试点至少覆盖素材、数据复盘和重复使用。记录人工基线、完成耗时、修改次数、最终接受、全部失败成本及复用行为。商业验证使用真实续用或采购意愿，广告效果提升需另有对照证据。

建议先完成每类 10 个代表任务形成评估集，再确定接受率和成本目标。样本数量是设计起点，可根据真实分布扩大；不是统计显著性保证。

定价、部署区域、素材格式和平台优先顺序尚未由用户冻结，使用 [决策记录](../governance/01-decisions-assumptions-and-questions.md) 中的默认方案推进评审。

## 9. 预设专业人员

角色入口先让客户选择能完成的工作，再描述目标和附资料；平台在授权范围内完成预置技能绑定。软件开发与测试、完整设计链路、营销分析与企业流程共用任务/成果体系。不同专业角色提供实质不同的方法和交付，而非仅更换称呼。

18 个角色的具体输入、流程、示例、产物和验收见 [角色分册](06-role-templates-and-skill-presets.md)。现有 marketing 客户可优先选择设计师、广告、电商、社媒、演示、视频及分析，软件开发覆盖为用户本次明确要求，不被首批客户画像排除。角色数量与资格门槛纳入 M1 角色发布，不以目录占位替代可用能力。

## 10. 平台管理后台

ADMIN01 将完整 Admin Dashboard 纳入产品必要范围。平台管理员使用独立登录和 MFA；客户企业 Owner/Admin 只管理自己的企业，不能获得平台后台权限。后台提供 16 个页面、8 类预设管理角色，完整用户目录和关系、用户消耗及费用钻取，支持管理员主动充值、赠送额度、调整信用上限、退款、开通及延期 VIP。

后台覆盖全部用户端云内容，包括会话、Agent/团队、资料/记忆、文件/成果、报告、流程和连接元数据，并能隔离、恢复、撤销分享及控制执行。具备正文权限的内容管理员可直接管理授权范围内内容；客服使用只读限时支持会话。动作权限、数据范围、字段、金额和有效期分别控制，普通合法操作可直接执行，高影响操作才按策略追加认证或独立审批。

VIP、实付余额、赠送额度、信用上限与执行预算分别管理，操作写入不可直接修改的账本/权益记录并跨端生效。用户可见目录、公告、帮助、菜单和功能开关经过草稿、预览、发布和回滚。后台沿用 CopyPaste 品牌，仍固定 Codex 与内部 AI 路径。详细页面和业务约定见 [Admin 产品设计](08-admin-dashboard.md)，开发拆分见 [技术设计 AD01–AD10](../technical/11-admin-control-plane.md)。
