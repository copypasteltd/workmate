## 1. 产品形态与核心承诺

Web 是企业云端 Agent 工作台。用户可以直接委派完整工作，Agent 使用获准的资料、技能和外部账户执行，在工作区交付可检查、可修改、可复用的成果。轻度用户指无需安装即可开始，不代表 Web 只提供简化聊天或残缺的业务能力。

首批深入做好 marketing 的创意生产、效果复盘、SEO/GEO 及重复工作；这些业务使用同一套 Agent、会话、项目、文件和执行系统。专业能力通过模板、技能及业务方案组合提供。

默认助手、专业角色、团队成员与 Routine 均使用 Codex。客户选择业务角色、Skill 与工作目标，产品不提供内核切换；内部模型配置与媒体能力分别管理，所有 AI 仍经公司内部服务器。实例化和任务恢复须遵守 [固定 Codex 的配置约束](../technical/02-runtime-and-ai-gateway.md)。

## 2. 核心对象及关系

| 对象 | 回答的问题 | 生命周期与关系 |
| --- | --- | --- |
| 企业 / 项目 | 为谁工作、谁能访问？ | 企业是隔离边界；项目保存共享规则、资料和资源引用 |
| Agent / 模板 | 由谁负责、按什么方法？ | Agent 是持久实例；模板初始化角色、推荐技能与工作示例 |
| Conversation 会话 | 在哪个讨论中继续？ | 一个 Agent 或 Agent Group 可有多个会话；一会话包含多个具体任务 |
| Task 任务 | 这次承诺完成什么？ | 有输入、交付条件、预算、步骤、结果和终态；attempt 表示一次执行尝试 |
| 云工作空间 | 执行中的文件在哪里？ | 项目共享资料与会话工作文件分区；逻辑文件长期保存，计算进程可休眠 |
| Artifact 产物 | 本次交付是什么？ | 引用不可变文件版本，可预览、审阅、继续修改并提升为项目资料 |
| Skill 技能 | 怎样稳定完成某类工作？ | 有版本的方法、输入输出约定和工具依赖；安装、启用、绑定和授权分开 |
| Tool / Connector | 具体操作什么、凭谁授权？ | 工具是原子动作；连接器提供业务系统访问，凭证由服务端管理 |
| Agent Group | 多个专业角色怎样一起完成？ | 持久团队有协调者和成员；每次工作形成可追踪分工，不等同后台临时子任务 |
| 解决方案包 / Routine | 如何复用工作方法？ | 包组合角色、技能和资源要求；Routine 保存重复委派与触发条件，不复制凭证 |

项目共享记忆与个人偏好分别保存。新建会话不会自动清除长期记忆；删除会话、删除记忆、删除项目资料是不同操作，界面分别说明影响范围。

## 3. 首页及首次使用

登录并确定企业后，直接进入“今天需要完成什么工作”的输入区。新企业可自动建立默认项目与助手；用户已有项目时默认选最近可访问项目，始终显示当前上下文。默认值不会把不同企业或客户资料合并。

主动作是输入目标、上传/拖入附件并发送。提供“根据商品图做一组广告”“分析广告报表”“准备每周营销复盘”等可编辑示例；点击只预填，不自动提交。项目、Agent、工作模式及预算以简短控件显示，普通任务继承有效默认值。

不要求先配置完整品牌、全部连接器或自建 Agent。需要准确促销价格、字体授权或广告数据时，说明该项影响，再就地补充；可执行部分先继续。商业账号创建、成员邀请和完整管理配置另有入口。

主导航按工作组织；营销制作、分析、SEO/GEO 是示例、模板和结果视图，不要求用户在不同业务子系统重复建立背景。会话的附件列表、云文件树与产物列表分别呈现；打开的文件可固定到右侧工作面板。

## 5. 会话与任务交互

开始工作可选助手、专业 Agent 或团队；不选择时使用默认助手。自动标题可编辑，支持历史搜索、置顶、归档和删除；切换会话不停止后台任务。

每条用户消息记录消息标识与附件版本。咨询可以只产生回复；具体委派创建任务；补充信息绑定原任务；对已结束产物提出修改，在原会话创建引用原版本的新任务。不会因为发送普通消息或刷新页面重复提交任务。

同一会话同时运行多个工作时，输入区显示本条消息的目标任务或“新工作”。涉及同一文件的写入检测版本冲突，不让并行 Agent 静默覆盖。取消某个任务不删除会话，也不取消其他独立任务。

## 6. 执行、先计划、仅咨询

默认“执行”：目标明确时直接使用已授权能力完成，只有阻塞信息或具体受限动作才打断。

“先计划”：先提出目标理解、范围、输入、步骤、交付及费用范围。用户可调整或开始执行；开始动作绑定 plan_version 和 input_hash，修改关键资料、范围或价格条件后旧确认失效。计划模式不预先运行图片/视频生成或业务写入；必要的已授权只读调查应准确标识，规划本身的模型费用照常计量。

“仅咨询”：讨论、解释和获准只读检查，可附资料与证据；不写业务文件、不发布、不创建计划、不调用生成媒体。需要执行时显式切换，不能由模型自行改变模式。模式约束与企业权限取交集，计划确认也不能代替平台授权或高影响动作批准。

## 7. Agent、技能与能力中心

ROLE01 补充 [18 个预设专业角色](06-role-templates-and-skill-presets.md)，覆盖软件开发到完整设计链路及原始分析/流程场景。首个角色版至少十二个不同合格角色可直接使用，包含开发、设计和 Codex＋设计 Skill＋Image 2 的设计师。平台预先完成必需包配置及发布，选择时自动绑定本项目允许的依赖；下面的手动安装管理用于定制，不作为每个客户使用预设的必经步骤。未验证条目不能计入可用数量。

默认助手开箱可用，预置素材创意、广告分析、SEO 内容和运营流程等角色模板。用户可查看职责、示例、技能、资料范围和所需连接，再使用、复制或在权限范围内创建自己的 Agent。Agent 配置更新生成版本，运行中的任务保持原版本；删除前说明运行任务、历史及私有记忆如何处理。

能力中心组织 Agent 模板、Skill、连接器和解决方案包。Skill 展示名称、来源、版本、用途、输入输出、依赖和当前状态；既可搜索并启用，也可由任务提出推荐。自定义方法可从已接受工作生成候选包，先预览和试运行再发布。

**可用技能 = 已安装且启用的版本 ∩ 项目允许范围 ∩ Agent/任务绑定 ∩ 当前用户及资源授权 ∩ 所需能力实测可用状态。** 安装技能不自动取得 Google/Meta 或文件权限，也不授权访问外部 AI 服务。普通停用作用于新任务；安全撤销或企业禁用立即阻止后续调用，包括旧会话，UI 说明差别。

自然语言默认自动选用合适的已授权技能；“/技能”是精准指定的快捷方式。无需用户理解 MCP 或内核配置。用户界面解释能做什么和缺什么，不显示内部 base_url、供应商密钥或协议接线细节。

## 8. 云文件与成果协作

会话附件是输入引用；云工作文件是执行过程的实际文件；产物是有明确交付语义的文件版本；项目资料是团队复用的已保存知识或素材。这四者可以引用同一文件版本，但权限、保留和可见范围不得含糊。

用户可以上传、浏览文件树、搜索、预览、引用文件或选区到对话；Agent 的修改显示新旧版本和修改摘要。图片支持画布/选区，视频支持时间段，文档支持文本锚点，报告支持证据与数据范围。首期支持范围按文件类型明确，不暗示所有专业文件都能原位编辑。

已审阅成果可下载、存入项目或交给下一任务。保存到共享资料前明确共享对象；对外分享按企业策略单独开启，默认无公开链接。共享产物不自动共享完整个人对话、未授权附件、私有记忆和连接凭证。

逻辑云文件持久存在不要求每个用户始终占用一台运行的云电脑；独占机器、远程实时画面和交互终端保留独立规格与启用门槛。Web 上传只访问用户主动选择的数据，不获得全盘权限。

## 9. 项目、人和专业团队

项目保存共享工作说明、品牌与资料、推荐 Agent、已发布技能版本、连接资源范围、交付标准及预算策略。创建新会话时显示继承摘要；运行冻结这些配置的版本，执行时重新检查权限。个人偏好不能覆盖企业禁止项。

人类同事可以在授权项目中查看共享任务、审阅文件和继续工作。Agent Group 则由协调者接收总目标，按职责为专业成员分配任务，依赖允许时并行；每个子任务展示负责人、状态、结果与费用。主任务交付清单由协调者统一核对，成员部分失败时不伪造完整成功。

用户可以直接指定某成员处理问题，或由协调者决定分工。创建团队及扩充成员受项目权限、预算和并发限制；Agent 推荐新角色先形成配置草稿，不自动无限创建。后台临时子任务可以是内核策略，和用户可保存的团队分别记录。

## 10. 连接缺口与异常恢复

实际需要某账户时显示依赖卡：用途、拟读取或写入范围、所需身份、可用替代。用户完成连接与资源选择后回到原会话、原任务和检查点，无需重发全部需求。连接前可继续无依赖工作；取消连接不丢已有产物。

待用户输入、待批准、待设备及能力不可用分别显示。断线重连获取权威快照并补事件；完成动画不是健康证据。任务完成、失败和待处理动作进入产品内通知，点击直达对应会话/任务。未配置的邮件或 IM 不自动发送。

## 11. 从一次工作到持续服务

用户可以说“以后每周一按这个口径做”，或从成果选择“保存重复工作”。系统整理成可编辑说明：执行 Agent/团队、输入来源、输出位置、时间与时区、预算、授权及异常策略。用户确认具体配置后激活，不要求先画工作流图。

每次触发创建独立运行，引用稳定方法和当前获准资源，结果回到项目和对应会话。暂停未来计划与取消当前运行分开。计划页显示下次时间、最近结果和异常；漏跑去重策略沿用通用触发规则。成熟流程可升级为结构化 WorkflowVersion；自然语言入口和确定性执行规则并存。

## 12. Web 阶段与可核查验收

| 阶段 | Web 设计范围 | 代表验收 |
| --- | --- | --- |
| M1 | 自然语言首页、会话管理、默认/专业 Agent 模板、基本 Skill 绑定、云文件、成果迭代、工作模式及实际营销交付 | 无完整品牌配置也能开始；真实文件可检查；切换/关闭页面后云任务可恢复；权限不足不误报完成 |
| M2 | 项目共享能力、可见的专业团队、解决方案复用、基础云端定时工作及首个正式广告连接器 | 两名同事复用同一发布方法；协调者汇总成员交付；重连不重复任务；停用计划不再新建运行 |
| M3/M4 | 扩展、本地桥接、完整 Desktop 与更多业务能力 | 使用相同 Agent、项目、会话和产物身份；本地能力边界如实呈现 |

这些是本轮建议的产品与排期基线，尚无用户预算/人力/日期承诺。新增 REQ-061–072 和 TC-061–072 记录具体边界；持续云文件属于 M1，独占云电脑仍单列为 REQ-059，不再把它们混为同一项远期能力。

## 13. 平台 Admin 与用户端一致性

ADMIN01 的完整后台见 [产品分册](08-admin-dashboard.md)，使用独立身份，不混入客户企业管理权限。用户冻结、费用/权益变化、内容隔离和公开目录发布经领域服务及版本事件影响本工作台；前端缓存不是授权依据，内容不可见时清除摘要/预览，VIP 开通后展示实际权益和来源。M1 同步具备人工费用/VIP 与管理基础，M2 完整批量/导出及公开配置发布；实际页面与跨端生效分别验收。
