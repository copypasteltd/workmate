# 部署、发布与运维手册

版本：1.5 · 2026-10-18。此为目标运维流程，本轮未部署或操作生产资源。

## 1. 环境与配置

dev、staging、production 分开数据库、对象前缀、OAuth 应用、签名 key 和 AI 额度。staging 使用与生产同协议的内部网关受限账户。正式域名、区域及云供应商待确认，文档不假称服务已留港部署。

发布组件为静态 Web、独立 Admin、API、worker、媒体 worker、设备控制面和客户端包。Admin 使用独立会话、身份回调、MFA、CSP 和受控入口，不能复用普通用户 Cookie。云端隔离与配额按架构实施；本地开发和操作不使用 Docker/WSL。

## 2. 发布顺序

备份及迁移校验 → 扩展型数据库迁移 → 后端灰度 → worker 排空/更新 → 合同 smoke → 独立身份/权限/审计检查 → Web/Admin 灰度 → 连接器/媒体逐项开关 → Desktop/扩展小范围发布 → 观察 → 扩大。

运行中的任务固定内核和工具版本；更新优先等待检查点或保留旧 worker 完成。破坏性协议变更先部署兼容读写，再升级客户端，最后移除旧字段。

内核发布和回滚仅在已经验收的 Codex 版本之间进行，记录二进制/包摘要、app-server 协议 schema、内部 provider 与回归结果。启动/恢复发现非 Codex、版本缺失或验证失效时拒绝执行；故障按现有重试/检查点规则处理，不自动切换内核或底层模型。升级不重写原任务绑定和已发生费用。

## 3. 回滚

关闭新能力入口，停止新作业投递并保留已接受任务；回滚程序到兼容版本。若数据库已有不可逆迁移，使用兼容程序或前向修复，不能直接删列或恢复旧库覆盖新账本。

客户端更新验证签名和摘要，失败回到可运行包。设备协议不兼容时停止新命令，保留历史查询和安全退出。

## 4. 日常观察

检查任务排队时间、失败类型、上游错误、未知动作/费用、连接 freshness、设备命令积压、对象引用异常和浏览器无主资源。检查费用预留与用量账本对账，按企业查异常峰值但不将正文放入监控。

## 5. 故障处理手册

| 情况 | 排查与恢复步骤 | 禁止的快捷修复 |
| --- | --- | --- |
| 任务长期 queued | 核对 task/outbox/队列投递和 worker 租约；使用原投递键重投 | 新建同内容任务掩盖丢失投递 |
| worker 中断 | 核对 fencing、步骤输出与外部 action；回收过期租约后恢复 | 并行运行两个具有写权限的接管者 |
| 内部 AI 故障 | 停止受影响能力新调用、保留任务和预留、等待恢复/对账 | 直接改用外部供应商绕过内部服务器 |
| 外部结果 unknown | 查 provider_job/action、回执和用量；无法确认则人工处理 | 自动重发可能发布/扣费的创建请求 |
| 费用未释放 | 对账 operation、usage 和 reservation，使用唯一调整事件修正 | 直接改余额或删除历史账本 |
| 浏览器内存上升 | 查看任务资源归属、租约和 cleanup；回收过期任务页面 | 关闭用户所有 Chrome 进程 |
| 设备离线 | 确认用户设备状态，任务保持 waiting_device；恢复先同步撤销 | 将目录权限迁移给未经授权设备 |
| 对象缺失 | 禁止新下载、核对上传完成记录、恢复版本或标失败 | 生成空文件并把状态改 ready |
| 误发额度或 VIP | 暂停同类新操作，核对 operation、主体、账项/授予版本；用获准扣回或撤销命令记录结果 | 直接改余额、删除授予历史或将赠送改作已收款 |
| 收款/退款未知 | 查原付款、回执、累计可退与幂等结果；进入 reconciling，核清后补偿 | 未确认便二次退款或凭截图直接标付款成功 |
| 权益到期仍显示可用 | 核对 UTC 时刻、源授予、当前版本与缓存；确认 API/worker 实时拒绝并重建投影 | 延长到期时间来掩盖调度故障 |
| Admin 凭证或角色异常 | 撤销后台会话/绑定，递增权限版本；停止相关队列与导出并按审计复核影响 | 以普通用户会话兜底或关闭 MFA |
| 审计写入故障 | 保持普通查询，阻止敏感写入，恢复审计存储并核对未完成事务 | 先发钱、后补不可核查日志 |

每次恢复动作关联 incident_id、操作者、范围和结果。通知客户按既有服务渠道和授权执行，本轮不发送外部消息。

## 6. 备份与恢复演练

目标 RPO/RTO 见 NFR。数据库备份与时间点恢复、对象版本和密钥配置分别验证；仅有数据库 dump 不能证明文件可恢复。备份密钥与备份数据分开保管。

恢复到隔离环境 → 检查任务/账本一致性 → 应用删除 tombstone → 将运行任务改为待核对而非自动重放 → 核对外部结果 → 验证对象引用、权限和核心流程 → 记录实际 RPO/RTO → 才决定恢复服务。

## 7. 容量和成本

按队列类型和企业公平分配并发；媒体占用、数据库连接与存储增长分别扩容。能力成本异常先限新增调用并调查，不通过清空费用记录掩盖。

## 8. 运维交付物

每个环境需有实际部署清单、锁定版本、配置来源、责任人、监控位置、备份位置和最近演练结果。当前这些部署事实尚不存在，后续记录于 docs/evidence 的受控脱敏材料，并由发布评审确认。
