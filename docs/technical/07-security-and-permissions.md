# 权限、执行与数据边界设计

版本：1.5 · 2026-10-18。本文落实企业 Agent 的实际执行边界，不构成已经通过安全认证或地域合规审查的声明。

## 1. 信任边界

外部用户和页面 → 客户端 → 产品 API → 业务服务 → 内核/执行器 → 内部 AI 与外部业务系统。每层收到的信息仍需按用途校验；模型输出、附件正文、网页文字和用户提供 URL 都不是授权凭证。

公司云端资料、企业/项目范围、预算和平台工具权限由服务端决定；本机资源权限由客户在本机选择。按 [CLIENT01](../requirements/03-client-execution-amendment.md)，Desktop 必须支持客户主动授予完整本机权限，不能将平台项目范围误当作唯一可访问的本机目录。模型生成的字段不构成新的企业身份或权限授权。

平台运行配置只允许受控 Codex 版本。内核程序、app-server 参数、provider 与 Skill 路径由可信配置解析，客户模板、上传文件或网页内容不能覆盖；发布、启动和恢复均校验 kernel=codex、版本、依赖与当前权限。Codex 自带权限设置与产品范围取交集，不能替代企业隔离、受控工具及网络出口约束。

## 2. 企业与对象隔离

API 授权、数据库组合外键/RLS、对象下载权限、SSE 和 worker scope 同时实施。迁移角色与运行角色分离，连接池事务级企业上下文不可串用；后台作业也必须有明确企业身份。

对象存储 key 不是授权令牌。普通下载签名有效期短，敏感下载经产品代理；CDN 缓存绑定对象版本，不把私人资产放进公共缓存。支持人员访问必须具备时限和范围。

## 3. 凭证与登录

供应商主密钥只在公司内部服务；平台 refresh token 用密钥引用保存；设备私钥在系统凭证设施。Web 使用 HttpOnly cookie、CSRF 和 Origin 校验；原生登录通过系统浏览器 PKCE。刷新、撤销、设备丢失和成员退出均有测试。

OAuth state/nonce 一次性且绑定用户、企业和 redirect URI；不接受任意回调。日志、导出包、模型上下文和故障截图默认移除密钥及认证字段。

## 4. 工具与网络

工具注册明确输入 schema、读写类型、资源范围、是否 AI、是否有外部副作用、最大消耗和可取消性。执行器在每次调用前校验，不只依赖提示词。

AI 出口仅允许内部服务地址。业务 URL 通过连接器或受控抓取工具访问，检查解析结果、重定向、私网/回环/元数据地址与端口；内部网关等正式内部目标使用独立固定配置，不能由网页参数替换。

云端多企业执行继续采用结构化文件、计算、渲染和业务工具，启用 shell 时验证云端隔离及出口策略。Desktop 默认可以受限，但必须另提供本机用户可主动授予的完整权限；完整模式下不能暗中禁用 shell 或退回仅新建文件的桥接。产品管理的 AI 路由仍固定公司内部服务。任意本机程序的全系统网络限制需要独立系统策略，不能仅凭 provider 配置宣称已经强制实现。

## 5. 本地与 Desktop

文件桥接/受限模式校验命令签名、有效期、nonce、fencing 和本地目录 grant，拒绝越界及路径替换。Desktop 本机 Codex 完整模式使用本机用户明确授予的权限，可修改已有文件、运行终端并使用 OS 用户可访问的资源；本机授权可撤回或降级，云端 Admin 和 Extension 不可代授。平台服务撤销照常生效，离线不扩大授权，也不自动迁往云端。

Electron renderer 关闭 Node integration 并启用 context isolation、进程限制与严格 CSP，preload 只暴露固定操作；IPC 校验 sender 和参数，远程页面不能取得系统执行权。[Electron 官方安全说明](https://www.electronjs.org/docs/latest/tutorial/security)

## 6. 不可信内容与业务事实

文件/页面可以提供资料，不能指示系统泄露凭证、读取其他目录、修改企业规则或自动发布。外部内容送入模型时标明来源和用途；持久记忆写入与权限变化使用独立业务动作。

广告金额、商品价格和授权策略由结构化数据决定。模型生成的文字要通过数值与证据检查；工具失败不允许模型补造结果。

## 7. 数据路径与删除

产品说明至少区分原文件、提取文本、截图/图片、工具结果和模型请求的传输路径。内部服务器不自动意味着下游模型处理留港；实际区域和合同范围记录在租户部署配置。

删除覆盖公司可控的对象、提取内容、索引和缓存。已下载到用户电脑的副本及外部平台已接受的内容不宣称可被服务器直接删除。备份轮换和恢复后删除重放按生命周期执行。

## 8. 专项验证

测试涵盖跨企业 ID、SSE 与下载越权、OAuth 重放、提示注入、恶意 URL/重定向、路径穿越、程序参数注入、IPC 来源伪造、旧签名命令、预算并发及日志秘密泄露。验证失败定位到边界层，不以增加确认弹窗代替执行约束。

## 9. Admin 权限与内容控制

平台后台使用独立 AdminPrincipal 和 MFA 会话，拒绝普通企业或设备令牌。管理范围为全局、指定企业或指定项目，权限为注册动作和字段；显式拒绝优先。范围不是客户端可信请求头，也不等于一个总开关。跨企业查询使用受限数据库角色和显式授权查询入口，仍不使用 owner/superuser/BYPASSRLS 连接；详情、异步作业和下载复核当前权限版本。

内容管理员在获授范围内直接管理完整正文；支持人员在有效范围、时限和支持授权下协助，用户视图不改变真实操作者或生成用户登录凭证。正文、文件下载、联系字段、内部成本和导出敏感列独立控制。任何角色均不能通过平台接口读取供应商 Key、密码摘要、会话/OAuth token 或设备私钥。

资金、VIP 与权限写入记录原因和版本，绑定稳定幂等/业务唯一键。普通授权操作直接执行；按金额、批量规模、角色提升等版本化策略才增加近期 MFA 或独立审批。审批绑定载荷摘要、对象版本、范围和到期，执行前重验，不能自批或通过审批后改参数增加权限。审计写入失败阻止敏感变更。

隔离立即阻断搜索、模型读取、预览、分享和下载，恢复只恢复当前合法访问，不恢复旧公开链接。后台文件预览采用隔离源/CSP/附件下载，用户 HTML、SVG 或文档脚本不能在 Admin 登录源执行。导出按源权限、字段、目的和有效期处理并防表格公式执行；下载经受控代理重验权限，不能交付绕开撤权的长期对象 URL。规则与验收见 [Admin 分册](11-admin-control-plane.md)。
