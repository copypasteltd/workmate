# Stage 83 · 可复核的 GEO 样本观测

本轮落实 REQ-030 / TC-030 中的固定问句、不可改写的配置版本、重复观察、原始回答与引用证据，以及消费产品人工样本的独立记录。原始验收状态不因这份设计或局部检查自动关闭。实施和测试结果另附实际凭据。

## 观测口径

API 样本由云端 Codex 经公司内部 Responses 网关运行。固定已审核 Agent 版本、角色及 skill 哈希、运行时、模型别名、推理配置、问句、请求地区、语言和观测协议版本。没有附加历史对话或项目记忆；不允许有绑定品牌的 Agent。此协议关闭业务工具和检索，不能标注成 ChatGPT/Grok 消费产品的实际搜索结果。请求地区是提示上下文，服务商实际处理地区未知。保存请求别名，不冒充服务商解析后的底层模型身份。

人工样本由用户选择消费产品、填写其显示的模型、实际使用的地区/语言、检索状态、观察时间并粘贴原始回答。人工记录标为用户提供，引用是回答中真实存在的 URL 或用户标注，平台不自动验证引用页面内容。人工样本不调用 AI、不产生模型费用，不进入 API 样本的汇总口径。

别名出现是对原始回答的确定性字面匹配，保留字符位置，不推断实体身份、推荐排名、因果关系或全网覆盖。缺失、失败、费用待核实都以未知或实际状态展示，不能填零。回答中链接只表示回答包含该链接，不等于独立检索证据。

## 数据与使用流程

1. 用户在 Web 的行销分析 / GEO 中创建问句集及品牌别名，选择不绑定品牌的 Agent。配置保存为不可改写的 experiment version；修改配置须基于已检查的版本哈希新建版本，保留旧版。
2. 用户明确提交每问预算后创建 API run。界面展示当前方案的可用任务名额；服务端在配额锁下检查是否足够承载整组问句。Starter 只有一个任务名额时不能绕过限制执行两题，用户可等待已有任务结束、建立较小问句集或主动处理方案权限。一次事务为全部问句建立独立的 ask 任务并预留预算；任一失败则全部回滚。每问一个无历史上下文的 Codex 任务，走现有任务调度、内部网关授权、账本和未知用量处理。重复执行建立新 run，不覆写旧回答。
3. 任务完成后，用户可保存已完成回答。服务端重新核对当前权限、配置来源和任务状态，把实际任务输出写入私有不可变文件，记录 SHA-256、观察时间、语言/地区、模型别名和字面别名位置。未完成任务保持待观测，失败任务保持失败；此保存操作不再调用模型。
4. 用户可在同一问句版本下录入一个或多个消费产品的回答。产品、用户报告的模型、语言/地区、检索状态组成独立的有效配置哈希。
5. 用户选择两个 run 比较。明确显示同配置重复观察或配置差异、API/人工来源差异；仅在相同问句文本下比较回答哈希与别名出现。可下载带完整配置、原始回答、引用来源和限制说明的 JSON。所有读取和下载都重新检查当前来源状态。

## 权限、生命周期与端侧边界

SQL100 新增 experiment、run、sample 三类内容，强制 RLS；项目写权限才能创建，私有记录仅创建者访问。完整 Agent 定义与其哈希都写入观测配置，后续同一版本重复执行重新校验配置、权限、模型能力和内部网关。Admin 的元数据、正文、隔离、恢复和删除分别沿用已有能力和项目范围约束，操作审计保留。配置正文不接受 admin 元数据操作原地改写。

默认保留 90 天。配置或 run 被隔离/删除/过期时，其任务、答案、导出与下游已读取内容都受来源门控；永久删除通过现有 erasure journal 回收原始回答、任务及私有派生文件。恢复父内容不会复活已经永久删除的子内容。迁移保留已有 SQL001–099、来源检查分支和公共函数 OID。

原始回答文件默认私有。用户通过既有明确发布流程生成共享副本时，发布记录仍保留 experiment/run/sample 来源；父观测隔离后，旧共享副本和后续托管读取也被阻断。平台无法撤回已被用户另存到服务以外的文件。费用只在真实预留账本已结算或释放时显示确认金额；未知用量保留待核实状态，不填零。导出在规范排序前做 JSON 值归一化，保留 ISO 时间，未捕获回答省略原文字段；原始 UTF-8 答案字节与 SHA-256 始终对应。

新增 [GEO 运行时契约](../contracts/geo-observation-openapi.json) 覆盖 11 个接口、14 个结构，契约来自运行时输入约束并由真实成功请求与响应校验；业务层的并发、配额、唯一性与权限条件继续由服务端检查。原设计 OpenAPI 保留，不用新增契约替代原始验收范围。

完整运行时路由清单同步加入这 11 项操作，保留原 454 项配置接口及一个仅模拟模式启用的充值接口；当前为 465 项配置接口，模拟模式合计 466 项。完整后端回归独立比较实际注册操作与清单，双向检查遗漏和多报。第 32 轮在批次 05 检出清单漏记新增路由并保持失败；更新元数据后使用新轮次完整复核，原设计 OpenAPI 不被覆盖。见[清单修复来源](../quality/geo-observation-inventory-repair.json)。

Extension 继续使用原生右侧 Side Panel，提供明确的云端 GEO 工作区入口。Desktop 的 Agent 仍只在本地运行；不得为了复用云端 GEO 任务接口改为云端执行。云端观测入口在浏览器中明确打开，不能宣称已经实现 Desktop 本地 GEO 协议。本轮新 GEO 工作区以 Web 为主，Desktop 现有本机任务、全权限撤销和无边框体验必须保持实际验证。

## 界面与验证

沿用 CopyPaste 品牌和现有双语/主题。修复 Web 长页滚动后固定偏好控件遮挡下载按钮的问题；验证窄屏、键盘焦点和滚动后的操作区。Desktop 保持无可见上下/左右滚动轨道、可实际滚动和聚焦，不移除进度指示。

验证需包含：纯函数匹配与配置分组；真实原生 PostgreSQL 的跨用户/跨项目隔离、并发版本、幂等、预算回滚、任务绑定防伪、人工/API 分离、过期/隔离/删除门控和迁移历史；真实 Codex 经合成内部网关的重复回答；实际 Web 交互、导出文件、截图与动图；所有既有平台用例保留，所有六个组件检查。合成数据不是客户业务收益、真实消费产品排名或全量原始验收通过的证据。

交互与客户端回执保留其实际源码快照。随后两处最新迁移预期更新为 100，历史 098→099 夹具明确限定到 99；产品和运行时不变，原有数据、来源 OID、预备查询与重复升级检查保留。[测试差异复核](../quality/geo-observation-migration-expectation-review.json) 保留完整前后字节及失败范围。最终 19 批回归资格复用第 33 轮源码一致的 01–07 批，并于第 34 轮重新执行 08–19 批，包含两个受影响测试文件。逐项比较当前运行时、实际执行测试/辅助文件字节，完整覆盖 76 个实际测试文件；旧失败不重新标记。检查点分别列出运行时字节一致和测试文件差异，不宣称早期回执具有后来测试文件的哈希。
