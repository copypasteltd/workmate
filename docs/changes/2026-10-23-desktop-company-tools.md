# 2026-10-23 · 本机 Codex 公司工具与设计产物

Desktop 原先只接通五个软件/页面角色的本机执行，设计角色无法在本机线程中调用公司生图与成果工具。本次接通 `copypaste` 原生动态工具：客户在本机选择设计师并授予权限后，由本机 Codex 调用公司 Image 2，沿用同一原生线程编辑图片，并通过明确版本的产物按钮下载到客户选择的位置。Agent 循环、文件和终端保持在本机；Extension 仍是原生右侧栏云端对话及附件入口。

本次扩展至 16 个角色的本机协议准入与固定 Skill 加载。公司资料、字体、设计渲染、营销指标及图片工具沿用现有业务实现和账本；云端 Worker 与本机执行分别注入其授权。视频与流程顾问的本机专用工具继续保留为未完成项，16 个准入角色不等同全专业工作流验收。

- 公司工具调用绑定原任务、原生调用 ID、线程与回合。更换 HTTP 幂等键不能改写已绑定的请求；已接受图片操作重试复用原结果。
- 工具事务明确绑定当前用户及租户，保留私有产物和行级权限；不提升数据库权限。
- 适配锁定原生运行时实际支持的 schema 序列化，严格比较可信协议投影。业务参数继续使用原始验证，非法尺寸、枚举与来源不会因此放行。
- 本机唯读在发出请求前拒绝公司写入工具。停止、撤权及退出取消拥有的请求；付费结果未知时停止后续调用并保留原始核对预留。
- 新会话固定公司工具版本；旧会话保留原始绑定。工具结果不向页面暴露供应商凭据或任意本机保存路径。
- UI 增加设计及营销角色、公司产物版本和系统保存入口；保留无边框窗口、无默认菜单及本机执行提示。
- 长对话改为消息区内滚动，保留输入、预算和开始/停止入口；实际检查默认及 800×600 最小窗口。

验证与可复现命令见 [本次源码、报告及实际录制检查点](../quality/desktop-company-tools-checkpoint.json)。检查使用真实锁定 Codex、真实 Electron、身份、文件、沙箱、项目 API、私有产物、下载及服务端账本；模型与 Image 2 响应以及系统窗口选择决定是用户授权的明确假数据夹具。初次联调失败报告保留，包括事务用户上下文和原生 schema 不一致的定位及后续修复验证。UI06–UI08 的业务与旧布局断言通过记录也保留；截图复查后增加输入、预算、费用、产物和全部祖先容器边界检查。只读示例明确回复写入被拒绝，实际文件字节另行核对。

本次绑定 818 项平台完整回归（63 个文件、16 批）、37 项客户端测试、14 项真实原生测试及 9 项实际打包旅程，均通过；六项恢复规则测试单独记录，不计入产品覆盖。当前媒体为 UI09 的六张实际截图、GIF 和 MP4，全部字节与完整解码已核对。

完整回归发现两项升级测试仍要求版本 91，修正为已发布的 92，继续严格检查版本相等；并复验有历史财务及审批数据的升级。单独升级复验与平台完整回归重叠，不相加为额外覆盖。

第 12、13 轮完整回归分别在 242、568 项已观察通过后中断，保留部分日志与停止状态观察，均未计为全量通过。完整回归改为预先固定全部 63 个测试文件、覆盖源码与原生二进制摘要，按 16 批独立执行和清理。只复跑未完成的批次，最终核对完整文件集合、逐批 TAP/清理摘要及源码未变化；不拼造单次 TAP，也不混用旧源码的局部通过。

已发布迁移 001–092 未修改。阶段 72 报告与旧媒体保留其原始源码范围。生产模型/图片质量、人工系统窗口、签名安装、全部角色/工具和 102 REQ/102 TC/NFR/G01–G10 仍须独立验收；原 81 项局部验证、21 项未证明、0 项完整验收状态未提升。
